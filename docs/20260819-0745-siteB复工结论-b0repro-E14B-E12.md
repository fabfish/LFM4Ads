## §0 术语与度量定义（继承，不重复定义）

macro AUC / pooled AUC / 噪声地板 / 配对差 / 判定枚举（PASS/INCONCLUSIVE/FAIL）定义见
[开放实验计划 §口径基线](./20260817-1215-开放实验计划-下一个关键MoE改动.md) 与
[E8910 结论](./20260816-1950-E8910结论-硬路由topk2最终形态.md)。
本文新增术语（均为本文判定实际用到的）：

- **site 内自足**：每个判定的全部臂（含 dense 对照）都在 site B 重跑，噪声地板由 site B 自己的
  dense 臂估计；禁止拿 site B 的 run 减 site A 的 run。作用点：本文 §2 所有 Δ 的减法与被减数
  都出自 `cache/macro_auc_27k_siteB/`。
- **floor_B**：`2 × sample_SD(b0repro dense 4 seed 的 test macro)`，样本标准差（n-1）。
  本例 `floor_B = 0.001354`（与 site A 的 0.00135 只做趋势对照，绝不混用）。
- **Δ_1 / Δ_2**：`Δ_1(s) = macro_s(tk1) − macro_s(dense_b0)`，
  `Δ_2(s) = macro_s(tk2) − macro_s(dense_b0)`，同 seed 配对。
- **coverage / load_ratio（E12）**：从 run json 的 `router_weights`（每层 `Embedding(15,5).weight`）
  重建 dispatch：`gate = softmax(W)`，每场景取 top-2 专家；`coverage` = 15 场景选中专家的并集大小
  （满=5），`load_ratio` = 专家负载 max/min（负载 = 每专家被选中场景数，均匀 = 15·2/5 = 6）。
  跨层最保守聚合：coverage 取最小、load_ratio 取最大。

**端点对称性声明**：本实验两臂（dense / moe tk1 / moe tk2）**使用同一端点（macro AUC）+
同一模型选择准则（argmax macro valid 选 epoch / early-stop）**，可核对每个 run json 的
`best_epoch` 字段（三臂均为按 macro valid 选出）。不存在"baseline 按一端点、实验臂按另一端点"的混表。

## 3. 结果

### 3.1 b0repro dense 基线 vs site A（C6 校验，sanity 非判定）

| seed | site B test macro | site A E10 参考 | diff |
|---|---|---|---|
| 42 | 0.730582 | 0.730582 | +0.000000 |
| 123 | 0.729614 | 0.729614 | +0.000000 |
| 456 | 0.730107 | 0.730107 | +0.000000 |
| 789 | 0.731200 | 0.731200 | +0.000000 |

**结论**：4 seed 全部与 site A 参考**逐位复现**（6 位小数），C6 校验 PASS（`--check-baseline`，
tol 5e-4）。这证明 site B 与 site A 在同一 CephFS 数据 + 相同数值环境下测量的是**同一个量**，
为 site B 内自足判定提供了基础。

### 3.2 E14-B：top_k 单调性（主判定）

| seed | dense (b0) | moe tk2 | moe tk1 | Δ_1 (tk1−dense) | Δ_2 (tk2−dense) |
|---|---|---|---|---|---|
| 42 | 0.730582 | 0.735836 | 0.734737 | +0.004155 | +0.005254 |
| 123 | 0.729614 | 0.734945 | 0.734650 | +0.005036 | +0.005331 |
| 456 | 0.730107 | 0.734322 | 0.733491 | +0.003385 | +0.004215 |
| 789 | 0.731200 | 0.736449 | 0.734948 | +0.003748 | +0.005249 |
| **mean** | 0.730376 | 0.735388 | 0.734457 | **+0.004081** | **+0.005012** |

- `floor_B = 2 × sample_SD(dense) = 0.001354`
- Δ_1 4/4 正、Δ_2 4/4 正；**每个 seed 都有 Δ_1 < Δ_2**（4/4）。
- Δ_1 mean = +0.004081（3.01× floor_B）；Δ_2 mean = +0.005012（3.70× floor_B）。

**判定（照预注册 §2.1 冻结表）**：`Δ_1 < Δ_2` 且 Δ_1 mean > floor_B 且 4/4 正 →
**top_k=2 为最优协作度**（"隔离 + 少量协作"），而非"越特化越好"。
强度登记：Δ_2 为 3.70× 地板、4/4 同号；Δ_1 为 3.01× 地板、4/4 同号。判定枚举见 §4。

**副产 sanity（非判定）**：Δ_2 mean = +0.005012 与 site A E10 的 +0.0050 **同向同量级**，
复现一致；不存在"site 间复现分歧"，不需改判 E10。

### 3.3 E12：专家利用率诊断

3 个含 `router_weights` 的 moe run（b0repro_moe_tk2_s42、b1_moe_tk2_s123、b1_moe_tk2_s456）
聚合诊断（`cache/macro_auc_27k_siteB/expert_usage.json`）：

| run | coverage(worst) | load_ratio(worst) | 判定 |
|---|---|---|---|
| b0repro_moe_tk2_s42 | 5/5 | 9.0 | collapsed |
| b1_moe_tk2_s123 | 5/5 | 11.0 | collapsed |
| b1_moe_tk2_s456 | 5/5 | 3.3 | collapsed |

跨层细节（例 b0repro_moe_tk2_s42）：3 层 coverage 均 5/5（专家全用上），但负载极不均衡，
如 layer2 `loads=[4,9,9,7,1]`（有专家仅被 1 个场景选中，几乎闲置），gate 熵 min/mean 为
1.151/1.475 < ln5=1.609（说明确实分化了，但分化不均）。

**判定（照预注册 §2.2 冻结表）**：`load_ratio > 3`（且 3 run 全一致）→ **collapsed**。
注意：此处的 "collapsed" 按冻结规则命中的是**负载严重不均衡分支**（load_ratio>3），
而非 coverage 低；实际 coverage 满 5/5。两者动作相同：→ **E12b（load-balance）**。

## 6. 科学解读与可检验预测（反直觉点）

**反直觉点**：E12 判"collapsed"字面是"坍缩"，但实测 coverage 满 5/5（没坍缩），是
**负载失衡**（有专家几乎闲置）。同时 E14-B 显示 top_k=2 优于 top_k=1（协作必要）。
两者合起来的机制图景：

- 专家已分化（coverage 满、gate 熵 < uniform），但 15 个场景路由的负载分配极不均（load_ratio 高达 11）；
- top_k=2 的收益来自"隔离 + 少量协作"，降到 top_k=1（完全隔离）后收益回落 0.00093（+0.00501→+0.00408）；
- 负载失衡意味着当前 top_k=2 的收益**尚未吃满**——有专家闲置说明存在被浪费的容量。

**可检验预测**（E12b 如何证伪本机制）：若"负载失衡导致容量浪费"成立，则加 load-balance
loss 后 Δ_2 应**进一步提升**（> +0.0050，同 seed 配对）；若加 lb 后 Δ_2 不升反降，则
说明负载失衡是**良性**的（路由"择优"而非"浪费"），应改走 E13（router 粒度升级）路线。
