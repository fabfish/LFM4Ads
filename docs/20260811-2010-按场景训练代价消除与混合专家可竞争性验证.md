## 一、为什么开这个新阶段

上一阶段（子任务调制交叉网格，共约 290 次训练）得到一个决定性的结构性发现：

| 变体 | 训练过程 | pooled AUC（3 种子均值） |
|---|---|---|
| 稠密基准 | 整批（每样本等权） | **0.7807** |
| 稠密基准 | 按场景（每场景等权） | 0.7666 |
| 全路由混合专家 + 冻结路由 | 按场景 | 0.7714 |
| 全路由混合专家 + 正常路由 | 按场景 | 0.7683 |
| 部分路由加共享 + 冻结路由 | 按场景 | 0.7656 |

两个关键量级：

- **按场景训练本身的代价 = -0.0140**（同一个稠密模型，仅训练过程不同）
- **混合专家在按场景约束内的最大收益 = +0.0047**（全路由+冻结 vs 同过程基准）

即：**前提的代价是收益的 3 倍。** 上一阶段所有工作（36 配置交叉网格、
三目标调制、alpha 扫描、表征用法、门控诊断）都发生在这个 -0.0140 的坑里。

**本阶段唯一的核心问题**：这 -0.0140 是「按场景梯度」的必然代价，
还是仅仅是当前实现方式（场景内均值 loss 累加）的缺陷？

若是后者且可修复，则混合专家（全路由+冻结路由）有机会从
「按场景约束内的局部最优 0.7714」提升到「全局可竞争」，
整条研究路线的价值判断将完全不同。

## 二、根因分析（已定位到代码）

`train.py` 中 `train_moe()` 的按场景循环：

```python
for s in tab_batch.unique():
    mask = tab_batch == s
    sub = {k: v[mask] for k, v in batch.items()}
    model(sub)
    loss = criterion(sub["logit"], sub["is_click"].float())  # 场景内均值
    loss.backward()                                          # 梯度累加
optimizer.step()
```

`criterion` 是 `BCEWithLogitsLoss()`（默认 `reduction='mean'`），
所以每个场景子批量贡献的梯度是**该场景内的平均梯度**，与其样本数无关。
累加后等价于目标函数

\[ L_{\text{当前}} = \sum_s \frac{1}{|B_s|}\sum_{i \in B_s} \ell_i \]

而 `train()` 的整批训练等价于

\[ L_{\text{整批}} = \frac{1}{|B|}\sum_{i \in B} \ell_i \]

两者仅当所有场景样本数相等时一致。KuaiRand-1K 各场景样本量差异很大，
因此小场景被系统性放大、大场景被压缩，而 pooled AUC 是样本加权指标 → 失配。

**修复方案**：把每个子批量的 loss 按其样本占比加权：

\[ L_{\text{加权}} = \sum_s \frac{|B_s|}{|B|}\cdot\frac{1}{|B_s|}\sum_{i \in B_s} \ell_i = L_{\text{整批}} \]

即 `loss = criterion(...) * (len(sub) / len(batch))`。
这样在**保留按场景独立前向反向**（子任务调制所需的按场景梯度依然可得）的同时，
使总目标严格等于整批训练的目标。

## 三、实验设计

### 决策一：命名（遵守 AGENTS.md，禁用无全称代号）

- 新旋钮：`--scenario-loss-weighting {equal, sample}`
  - `equal`：现状（每场景等权），保留以复现历史结果
  - `sample`：新方案（按样本占比加权，理论等价整批）
- 产物后缀：`_samplew`（`equal` 为默认，不加后缀以兼容既有产物）

### 决策二：先做最小判别性验证，再决定是否铺开

先只跑**稠密基准**的 `sample` 加权（3 种子）。它是唯一能干净回答
「加权是否消除代价」的实验，因为它与整批训练同模型、同数据，
唯一差异就是训练过程：

| 变体 | 期望 pooled | 判定 |
|---|---|---|
| 稠密 + 整批 | 0.7807（已有） | 上界参照 |
| 稠密 + 按场景 + 等权 | 0.7666（已有） | 下界参照 |
| **稠密 + 按场景 + 样本加权** | **待测** | 若 ≈0.7807 → 代价可消除，继续；若仍 ≈0.7666 → 代价内生于按场景切分，路线需重估 |

这是本阶段的**关卡实验**（gate）。只有通过才进入第四节的铺开。

### 决策三：通过后的铺开范围（3 种子，串行双卡）

| 模型 | 路由 | 加权 | 目的 |
|---|---|---|---|
| 全路由 | 冻结 | 样本 | 主候选：能否超过 0.7807 |
| 全路由 | 正常 | 样本 | 路由学习在无失配下是否仍有害 |
| 部分路由加共享 | 冻结 | 样本 | 共享专家是否仍为负担 |

共 9 次预训练。若「全路由 + 冻结 + 样本加权」超过稠密的 0.7807，
则混合专家路线首次取得**全局可竞争**的证据。

### 决策四：调制旋钮暂不重跑

上一阶段已证明调制增益可被冻结路由平替（差 ≤0.0007，远小于噪声）。
在新加权方案下重跑 36 配置网格无价值，除非第四节显示
「正常路由 + 样本加权」反而优于「冻结路由 + 样本加权」——
那才说明路由在无失配条件下是有用的，此时才值得重开调制维度。

### 排除清单（明确不做）

- 36 配置交叉网格在新加权下重跑（理由见决策四）
- 模块级 / 模型级表征用法（特征级传导性已证不成立）
- 门控逐轮时序追踪（机制已由冻结路由判别性实验结案）
- 专家数 K 扫描（已证 K=2/4/8 无实质差异）
- 部分路由加共享的调制维度（该模型在所有口径下都劣于全路由）

## 四、测量口径（沿用并强化）

- 设备 cuda:0 / cuda:1，同配置独占单卡；跨变体串行、控制变量
- 种子 42 / 123 / 456，数据洗牌开启
- 主指标 pooled AUC（`test_auc_all`），辅助按场景 AUC 均值
- **判定标准**：3 种子 Δ 同号且 |Δ均值| 超过同变体基线的种子间极差（噪声地板）。
  已知噪声地板：稠密整批 0.0017、稠密按场景 0.0036、
  全路由冻结 0.0010、全路由正常 0.0036、部分路由冻结 0.0013
- **强制前置检查**（上一阶段最大教训）：任何跨模型比较前，
  先确认两者训练过程（损失归约方式、优化器、早停、洗牌）完全一致，
  否则测到的是过程差异而非模型差异

## 六、执行顺序

1. 改 `train.py` + 预训练脚本，lint 通过。
2. 冒烟：稠密 + 按场景 + 样本加权，单种子跑通并确认 loss 量级正常。
3. **关卡实验**：稠密 + 按场景 + 样本加权 × 3 种子，与 0.7807 / 0.7666 比较。
4. 若通过 → 铺开决策三的 9 次预训练（双卡串行）。
5. 汇总落盘，判定混合专家是否首次取得全局可竞争证据。
6. 若关卡未通过 → 记录「按场景梯度的代价内生」这一结论，
   并据此重估整条子任务调制路线是否继续。
