## 一、目的

此前所有 MoE 结论都在**轻量模型**（删掉三大 ID 表 video_id/author_id/music_id，
0.87M 参数）上得到。用户要求补齐公平性：**加回这 5.5 亿 ID 参数后，MoE(top_k=2)
的收益是否仍然成立、绝对 AUC 是否变化。**

## 二、口径（严格对齐，与轻量模型唯一区别是"加回 ID 表"）

| 项 | 值 |
|---|---|
| 数据 | KuaiRand-27K，full 36 字段，dim=360 |
| 模型 | dense vs moe(K=5, top_k=2 hard routing) |
| 参数量 | dense 551,317,475 / moe 551,317,700（**+225 router，参数量守恒**） |
| 优化器 | **dense AdamW（wd=0.01, lr=1e-3）**，与轻量模型完全相同 |
| loss | balanced（沿用 E7/E10 主口径） |
| 主终点 | macro AUC（8 场景等权），噪声地板 **0.00135** |
| seed | 42/123/456/789，同 seed 同卡配对 |
| 选点 | 精确 argmax(macro valid) |

**公平性**：full-ID 的 dense 与 moe 用**完全相同的优化器、超参、数据、seed**，
唯一变量仍是"是否按场景路由"（+225 router）。配对差干净隔离路由变量。

## 三、关于 sparse 加速的探索结论（记录，供后人参考）

用户最初要求"把训练速度优化到最快"。实测结果**推翻了 sparse 的预期收益**：

| 方案 | step 耗时（1K vocab 84M 参数 benchmark） |
|---|---|
| dense AdamW（PyTorch C++ kernel） | **12.3 ms** |
| sparse + SparseAdamW（Python 实现） | 30.9 ms |

- **dense AdamW 反而更快 2.5 倍**：PyTorch 对 550M 参数做全量向量化更新极快；
  自写的 Python 稀疏实现被 `index_select/index_copy` 的 gather/scatter 拖慢。
- **更关键**：sparse（SparseAdam）有**本质语义差异**——dense AdamW 对"未访问行"
  每步做 weight decay 衰减 + 动量 m/v 衰减 + 历史动量继续推动参数，这个演化是
  非线性的、无法 O(1) 稀疏复刻（对齐单元测试实测被访问行 diff 达 0.0126）。
  因此 sparse 无法满足"严格对齐"。

**结论**：放弃 sparse，用 dense AdamW。full-ID 实测 47.5ms/step、~20min/epoch、
~5h/run（可接受），且**零语义差异、严格对齐**。

## 四、判定规则（冻结）

沿用 E7/E10 预注册的规则，不因 full-ID 改阈值：

```
Δ_moe(seed) = macro_test(moe top_k=2) − macro_test(dense)，同 seed 配对
噪声地板 0.00135（= 2 × SD(dense 臂 macro 跨 seed)，27K 实测）
```

| 判定 | 条件 |
|---|---|
| **PASS** | 4/4 seed Δ>0 且 mean(Δ) > 0.00135 |
| **FAIL** | 4/4 seed Δ<0 |
| **INCONCLUSIVE** | 跨 seed 变号或效应在地板内 |

## 五、成本与预期

- 8 run（dense/moe × 4 seed），双卡并行，每卡 4 run × ~5h ≈ **20h**。
- 预期：轻量模型 MoE 收益（+0.0050）的机制是"参数隔离缓解跨场景干扰"，
  full-ID 下隔离机制不变，但 ID 表可能引入过拟合（1K 根因 1：lr=1e-3 解冻 ID 表
  会 epoch1 崩到 0.67）。需观察 full-ID 下是否仍收敛、MoE 收益是否仍在。
