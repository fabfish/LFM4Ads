## 一、要回答的问题（一句话）

**把「训练中按哪个 valid 指标选 epoch / early-stop」（即模型选择端点，定义见[归因文档 §0.4](./20260817-1208-突破归因-公平比较下的正面结果.md)）从 macro 换成 pooled，MoE 相对 dense 的收益是否仍然成立？**

这不是重复实验。已有实验（E7–E11）只报告了「选择端点 = macro」这一种规则下的结果；`pooled` 选择规则会取到**另一份权重**（E10 的 moe seed=42：macro 选 ep7，pooled 选 ep16），其 test 表现从未被测量。

### 1.1 已有的零成本证据（valid 侧，不足以定论）

从已落盘的 `history`（每 epoch 的 valid 指标）可**免费**算出：若改用 pooled valid 选 epoch，被选中那一 epoch 的 **valid** macro 是多少。

| 口径 | Δ_moe（valid macro，选择端点=macro） | Δ_moe（valid macro，选择端点=pooled） |
|---|---|---|
| E10（轻量 + top_k=2） | +0.004510，4/4 正 | +0.004241，4/4 正 |
| E11（full-ID + top_k=2） | +0.005421，4/4 正 | +0.006146，4/4 正 |

选择惩罚（改用 pooled 选择后，被选中 epoch 的 valid macro 损失）：E10 dense −0.003230 / moe −0.003499；E11 dense −0.001839 / moe −0.001115。

**方向性结论：两个臂都被惩罚，惩罚量级相近，Δ_moe 仍 4/4 正。**
**为什么仍不足以定论**：这些是 **valid** 数字，而 valid 正是选择所用的集合 → 存在选择偏置（selection bias），不能当作泛化结论；判定必须用 **test**。E15 补的就是 test 侧。

## 二、设计：一次训练同时产出两套选择结果

**关键做法（零额外训练成本、完全配对）**：训练轨迹只跑一遍，但在训练过程中**同时维护两份 checkpoint**——`best-by-macro-valid` 与 `best-by-pooled-valid`，训练结束后各自在 test 上评估一次。

```
每个 epoch:
    训一轮 → 算 valid(macro, pooled) → 算 test(macro, pooled)  ← 全部落盘
    若 valid_macro  刷新历史最好 → 存 checkpoint A
    若 valid_pooled 刷新历史最好 → 存 checkpoint B
    两个都没刷新 → patience 计数 +1（计满 10 停）
训练结束: checkpoint A 与 B 各在 test 上评估一次
```

- 实现：`experiments/main_macro_auc.py` 新增 `--selection {macro,pooled,both}` 与 `--eval-test-each-epoch`（默认关闭，不改变历史行为）。
- 因为**两套选择共享同一条训练轨迹**（同 seed、同数据顺序、同优化步），二者之差**只含"选了哪个 epoch 的权重"这一个变量**，不含任何训练随机性。
- 每 epoch 的 test 指标也全部落盘 → 事后可复现**任意**选择规则（含"最后一个 epoch""固定 ep5"等），无需重跑。

### 2.1 矩阵（8 run）

| 变量 | 取值 |
|---|---|
| arch | `dense` / `moe`（K=5, **top_k=2**，即 E10 最终形态） |
| seed | 42, 456（→ cuda:0）；123, 789（→ cuda:1） |
| 其余 | 轻量模型（0.87M）、`balanced` loss、lr 1e-3、batch 10000、**max_epochs 20 / patience 10**（与 E10 完全相同的训练预算） |

同一配对 seed 的两个 arch 跑同一张卡（遵 AGENTS §2 并行规则）。

### 2.2 与 E10 的关系：内置复现哨兵

E15 的 `selection=macro` 分支应**复现 E10** 的 test macro（同 seed、同预算、同轨迹）。允许的偏差来源仅有：E15 的 early-stop 条件更宽（两端点都不改善才停），可能多跑几个 epoch，若 macro 在更晚的 epoch 又刷新纪录，则 argmax 可能后移。

- **哨兵判据**：若 `|E15(selection=macro) − E10|` 在 4 个 seed 上均 < 0.0005（≈0.37×地板），记为**复现通过**；否则整个 E15 结果**作废重查**，不得解释为新发现。

## 三、full-ID（E11 口径）为何不纳入本轮

full-ID 单 epoch 约 20min（vs 轻量 3.4min），8 run 需 ~40h。本轮先用轻量口径（E10 最终形态）给出 test 侧结论；full-ID 只保留 §1.1 的 valid 侧读数，并在结论文档中**明确标注为"未做 test 侧验证"**。若轻量口径下出现"pooled 选择使 MoE 失效"，再花 40h 补 full-ID。

## 四、判定规则（启动前冻结，跑完不得修改）

主指标：**test macro AUC 的配对差** \(\Delta_{\text{moe}} = \mathrm{macro}^{\text{moe}} - \mathrm{macro}^{\text{dense}}\)（同 seed、同卡、同轨迹）。

对**每一种选择规则**分别判定，规则同 [E5 预注册 §4](./20260815-0018-场景内泛化MoE长程矩阵预注册.md)：

- 噪声地板 = \(2\times\mathrm{SD}(\text{dense 臂的 test macro across seeds})\)，**在该选择规则内各自计算**；
- `PASS` = 4/4 seed 同号为正 且 均值 > 该规则自己的噪声地板；
- `INCONCLUSIVE` = 上述任一条不满足；
- `FAIL` = 4/4 同号为负且幅度超地板。

**预注册的三种可能结局与各自的解释（先写死，防事后叙事）**：

| 结局 | 含义 | 对已有结论的处理 |
|---|---|---|
| **A. 两种选择规则都 PASS** | MoE 收益对选择规则不敏感 | 已有结论强度**上调**：附加"对选择端点稳健"这一条 |
| **B. macro 选择 PASS、pooled 选择 INCONCLUSIVE/FAIL** | 收益依赖"按 macro 选 epoch" | 已有结论**必须加限定词**："收益在以 macro valid 做模型选择时成立"，并在摘要与 README 中同步；不得省略 |
| **C. 两种都不 PASS** | E10 结论无法复现 | 触发 §2.2 哨兵排查；若哨兵通过则 E10 结论**降级为 INCONCLUSIVE** |

另外报告（不参与判定，仅登记）：
- 两种选择规则各自的 test **pooled** AUC 配对差；
- 选择惩罚（test macro）：`test_macro@pooled选择 − test_macro@macro选择`，分 arch 报告；
- 两臂各自被选中的 epoch。
