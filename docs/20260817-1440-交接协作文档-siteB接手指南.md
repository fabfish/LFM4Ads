## 一、术语（本文自包含，不看别处也能懂）

| 术语 | 定义 |
|---|---|
| **场景（scenario）** | 数据里的 `tab` 字段，表示这次曝光发生在 App 的哪个板块（取值 0–13）。场景之间样本量与点击率差异极大：s1 占训练 65.6%、CTR 0.4366；s3 占 0.34%、CTR 0.0206（**相差 26 倍**） |
| **AUC** | 随机取一个正样本和一个负样本，模型给正样本更高分的概率。**完全由「正负样本对中排对的比例」决定** |
| **pooled AUC** | 把所有场景样本倒进一个池子算一次 AUC。分母**包含"正样本来自场景 A、负样本来自场景 B"的跨场景对** |
| **macro AUC** ★主终点 | 在每个场景**内部**各算一次 AUC，再对 **8 个场景等权平均**（场景集合固定为 `{0,1,2,3,4,5,6,8}`）。**只含同场景对，每场景权重恒为 1/8** |
| **端点（endpoint）** | 指定"用哪个指标做决定"的约定。一次 run 里有两个决定点：**决定 A** = 训练中按哪个 valid 指标选 epoch / early-stop；**决定 B** = 训练后按哪个 test 指标判 PASS。本项目**两处都用 macro AUC** |
| **配对差（paired delta）** | \(\Delta = \mathrm{AUC^{moe}} - \mathrm{AUC^{dense}}\)，**同 seed、同 site、同卡**。这样两臂共享了数据副本/随机数流/GPU/驱动，Δ 才能归因于架构差异 |
| **噪声地板（noise floor）** | \(2\times\mathrm{SD}(\mathrm{dense\ 臂端点\ across\ seeds})\)。含义：**同一个模型只换随机种子就能产生的波动幅度**。效应小于它就无法与随机波动区分 |
| **地板倍数** | \(\lvert\overline{\Delta}\rvert / \text{floor}\)，跨实验比较强弱的**唯一**可比量 |
| **判定枚举** | `PASS` = 全部 seed 同号为正 **且** 均值 > 地板；`INCONCLUSIVE` = 任一条不满足（**注意这不等于"没用"，而是"这个设计测不出来"**）；`FAIL` = 全部同号为负且超地板 |
| **软路由 / 硬路由 top_k** | 软：K 个专家全部参与前向与反向，按 gate 加权。硬 top_k=2：只保留 gate 最大的 2 个，其余置零 → **每场景只有 2 个专家收到梯度**。参数量完全相同（激活稀疏，非参数稀疏），wall 0.98×，**不省算力** |
| **参数守恒** | `CrossExpertLayer` 把 `Linear(330,330)` 拆成 K 个 `Linear(330,66)` 后 concat，总参数精确不变。moe − dense = **+225**（3 层 × 15 场景 × 5 专家的 router），占 0.026% |
| **哨兵（sentinel）** | 一个"本该没有效果"的对照臂。若它也出现效果，说明测量链路有问题。例：`frozen-router` MoE（gate 恒为 1，与 dense 代数等价），实测 ≈0 |
| **site** | 一台独立机器 + 它自己的数据副本、驱动、torch。**site A** = 现有 2 卡机，**site B** = 你 |

## 二、模型与数据（你要跑的东西到底是什么）

### 2.1 模型

DCNv2：3 层 Cross Network + 2 层 DNN + head(15)，特征维度 dim=330。

| 变体 | 参数量 | 说明 |
|---|---|---|
| **轻量 dense**（本阶段基线） | **869,525** | 去掉 `video_id / author_id / music_id` 三张高基数 ID 表 |
| **轻量 moe**(K=5) | **869,750** | 仅多 225 个 router 参数 |
| full-ID dense | 551,317,475 | 保留 ID 表；**已证明有害**（27K 上 macro 降 0.0055，4/4 seed 负），本阶段不用 |

为什么删 ID 表不是作弊：ID 平均曝光 2.6 次、test 74% OOV，那些参数只能学噪声；且 site A 已花 20h 用 full-ID 复核过（E11），MoE 收益依然 PASS（+0.004329，地板 3.24 倍）。

### 2.2 数据

KuaiRand-27K，3.22 亿行。切分按日期：`train: date<20220503` / `valid: [20220503,20220506)` / `test: ≥20220506`。

| 集合 | 行数（**必须精确一致**） |
|---|---|
| train | 255,474,457 |
| valid | 34,034,748 |
| test | 32,769,180 |

显存：训练时全表常驻 GPU（`GpuBatches`），约 **61GB/卡**。若你的卡小于 80GB，先报回来（§8），不要自行改 batch_size——那会破坏配对口径。

## 四、五条纪律（违反会让实验作废，请务必读完）

### 4.1 跑任何矩阵前，preflight 必须全绿

```bash
python scripts/verify/preflight_site.py --site B
```

校验 6 项（参考值由 site A 于 2026-08-17 冻结在脚本 `REFERENCE` 常量中）：

| 检查 | 内容 | 期望值 |
|---|---|---|
| C1 | 数据集字节数 + 前 64MB sha256 | 6,005,554,962 |
| C2 | vocab json 可读（user 27 / video 9 字段） | PASS |
| C3 | 切分样本量 | 255,474,457 / 34,034,748 / 32,769,180 |
| C4 | macro 场景集合 | `{0,1,2,3,4,5,6,8}` |
| C4b | 参数量 | dense 869,525 / moe 869,750（router 225） |
| C5 | torch / cuda / GPU 名 / TF32 | **只记录，不要求与 A 相同**；但 **TF32 开关若与 A 不同（A 为 False）必须在结论中登记** |

任一 FAIL → **停下报回（§8）**，不要"先跑起来再说"。

### 4.2 同一个 seed 的所有臂必须在同一张卡

三卡映射（已写死在 `run_macro_auc_matrix.py` 的 `_SEED_DEVICE_BY_SITE["B"]`）：

| device | seeds |
|---|---|
| cuda:0 | 42, 789 |
| cuda:1 | 123 |
| cuda:2 | 456 |

3 不整除 4，所以 42 与 789 共卡。**绝不允许把某个 seed 的 dense 与 moe 拆到两张卡**——那会把设备差异混进配对差里。

### 4.3 端点与模型选择两个臂必须完全一致

- 决定 A（选 epoch / early-stop）= macro **valid** 的精确 argmax；决定 B（判 PASS）= macro **test** 配对差。
- 两个臂走同一份 `train_arm()` 代码，落盘的 `provenance.model_selection` 可核对。
- **禁止**出现 baseline 按一个端点、实验臂按另一个端点的比较。

### 4.4 ★最重要：绝不跨 site 相减

**禁止**：拿 site B 的 moe 减 site A 的 dense；用 site A 的地板 0.00135 判 site B 的效应；把两端 Δ 合并求均值。

**原因**：配对差之所以可信，是因为两臂共享了数据副本、随机数流、GPU 型号、cuDNN 版本、TF32 开关、torch 版本。一旦把同一配对的两臂分到两台机器，这些混杂因子全部回到 Δ 里，而它们的量级未知、可能与效应（+0.005）同阶。届时 Δ 无法归因于"MoE vs dense"。

**因此**：分配粒度是**整个实验**（含它自己的 dense 对照臂）。每个实验必须 **site 内自足**——判定不需要另一 site 的任何数字。两端之间只交换**结论与代码**。

> 唯一的例外是 **B0 的可比性校验**：它把 site B 的 dense 与 site A 的 dense 逐 seed 比对（容差 5e-4）。这是"两台机器是否在测同一件事"的健康检查，**不是配对差**，且只比 dense-vs-dense、绝不参与任何判定。

### 4.5 判定规则跑前冻结，跑完不许改

- 阈值全部硬编码在 `scripts/summarize/*.py` 里，**不要改**。
- 不得事后更换端点、场景集合、seed 集合、地板算法。
- 不得用跨 seed 均值掩盖变号（4 个 seed 里有 1 个反向 → 就是 `INCONCLUSIVE`，不是"整体为正"）。
- 结论强度只用 `PASS/INCONCLUSIVE/FAIL` + 地板倍数 + 同号 seed 数。**禁止**写"显著提升""效果明显"。

## 五、你的任务队列

统一口径（**除各任务注明的唯一变量外，全部不得改动**）：27K、轻量模型（869,525 参数）、`balanced` loss、K=5、lr=1e-3、batch 10000、`max_epochs 20 / patience 10`、macro AUC 主终点、macro valid 精确 argmax、4 seed(42/123/456/789)。

### B0：入场券（≈4h，必须第一个做）

一次达成三件事：

1. **建立 site B 自己的 dense 基线与噪声地板**（dense × 4 seed）——后续所有判定都用它，不用 A 的。
2. **可比性验收**：与 site A 的 dense 逐 seed 比对，容差 5e-4。
3. **E12 专家利用率诊断**：moe(K=5,top_k=2) × seed 42 一个 run。

```bash
./scripts/matrix/run_siteB.sh b0repro                          # 5 run
python scripts/verify/preflight_site.py --site B --check-baseline
python scripts/diagnose/diagnose_expert_usage.py
```

**E12 想回答什么**：硬路由 top_k=2 的收益，是不是真的来自"不同场景走不同专家"？如果 15 个场景全都选同样那 2 个专家（**专家坍缩**），说明只用了 2/5 的容量，还有空间；如果已分化，那瓶颈就在路由粒度。

**为什么几乎免费**：`ScenarioRouter` 是 `Embedding(15,K)`，gate **只看 `tab`、与样本内容无关**，所以 3 层 × 15 场景 × 5 专家 = **225 个浮点数**就能完整还原全部 dispatch 决策，零额外推理。

**判据（冻结，不许调）**：

| 观测 | 判定 | 下一步 |
|---|---|---|
| 专家覆盖数 = 5 且负载 max/min ≤ 2 | 已分化 | 粒度是瓶颈 → 做 B2 |
| 覆盖 ≤ 3 或负载 max/min > 3 | **坍缩** | 先做 B2b（load-balance） |
| 覆盖 4、负载 2~3 | 部分分化 | B2 优先，B2b 补做 |

**B0 的门禁**：可比性校验 4/4 seed 在 5e-4 内 → 继续 B1。任一超容差 → **停下**排查（TF32 / 数据副本 / torch 版本），不要带着未解释的偏差往下跑。

### B1：top_k 单调性（≈4h，无依赖）

**问题**：top_k 从 5（软路由）降到 2，收益放大了 2.66 倍。**继续降到 1**（每场景只走 1 个专家）会继续涨，还是回落？

- 涨 → 机制是"越特化越好"，值得去做真条件计算（既省算力又更强）；
- 落 → 机制是"存在最优协作度"，专家间需要少量协作。

```bash
./scripts/matrix/run_siteB.sh b1topk        # 8 run: top_k=2 与 top_k=1 各 4 seed
```

dense 臂复用 B0 的 4 run。**唯一变量是 top_k，参数量完全不变** → 严格公平。

**判据**：\(\Delta_1 = \mathrm{macro(top\_k{=}1)} - \mathrm{macro(dense)}\)，同 seed 配对，地板用**你自己的** dense 臂算。与 \(\Delta_2\)（site A 实测 +0.005012，仅作趋势参照，**不可相减**）比较趋势。

| 观测 | 结论 |
|---|---|
| \(\Delta_1 > \Delta_2\) 且 4/4 正 | 单调"越特化越好" |
| \(\Delta_1 < \Delta_2\) 但 > 地板 | top_k=2 最优，机制 = 隔离 + 少量协作 |
| \(\Delta_1 <\) 地板 | 过度特化有害 |

**禁止**：不得声称 top_k 省了算力——当前实现是激活稀疏（5 个专家仍全算），site A 实测 wall 0.98×。

### B2：router 粒度升级（≈12h，**关键 MoE 改动**，等 site A 的 T2）

**问题**：现在的 `ScenarioRouter = Embedding(15,K)` 只有 **15 种 gate 模式**——每个场景一套固定权重，**与样本内容完全无关**。而 MoE 的本质是"按输入条件化"。**样本级路由从未被测过**，这是整个设计里表达力最弱的一环。

| 臂 | router | gate 模式数 | router 参数 |
|---|---|---|---|
| A（基线，复用 B1 的 top_k=2） | `ScenarioRouter` | 15 | 225 |
| **B** | `DataRouter = Linear(330,5)`，样本级 | 连续 | **4,965** |
| C | `Hybrid = Linear(330,5) + Embedding(15,5)` | 连续+场景 | 5,190 |

**参数不守恒必须登记**：B 比 A 多 4,740 参数（占模型 0.55%）。**不得写"参数量相同"**。缓解论证：dense 加宽 4× 的容量收益≈0，故 0.55% 应可忽略——**但这是推理不是测量，必须在结论里显式写出这条推理链**。

判据同 §四：4/4 正且超地板 → PASS（粒度确是瓶颈）；4/4 负 → FAIL（粒度路线关闭）。

### B3：AdaTask 对照（≈8h，等 site A 的 T3）

详见 [E16 预注册](./20260817-1410-E16-AdaTask对照预注册.md)。**先读那份文档再动手**，因为这里有个坑：

**历史实现是数值空操作。** 老代码做的是 `param.grad.mul_(f)` 然后 `AdamW.step()`。但 AdamW 的更新是 \(m_t/\sqrt{v_t}\)，梯度整体乘常数 \(c\) → \(m\to cm,\ v\to c^2v\) → **更新量完全不变**（恒等式）。site A 已用 200 步数值实验证实：梯度放大 100 倍与不放大，最终参数相对偏差 **1.9×10⁻⁷**（浮点噪声）；而时变因子确实有效（偏差 0.37）。证据：`cache/adam_scale_invariance.json`，可用 `python scripts/diagnose/diagnose_adam_scale_invariance.py` 秒级复现。

所以 B3 是四臂：N（无调制）/ **P（历史实现，作证伪哨兵，预期 |Δ| < 地板）**/ Q（post-preconditioner encourage）/ R（post-preconditioner suppress，**主假设臂**）。**不得跳过 P 直接跑 Q/R**，否则无法区分"修好了"和"本来就有效"。

## 九、常见问题速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 每个 run 都 `S1 FAILED: {...} != {...}` | 漏了 `LFM_SAMPLE_COUNTS_JSON`，守卫在拿 1K 行数比对 | 用 `run_siteB.sh` 启动（已固化五个变量） |
| 参数量显示 551,317,475 | 没走轻量路径（误加了 `--full-embeddings`） | 本阶段一律不加该参数 |
| cuda:2 一直空闲 | 漏了 `LFM_SITE=B`，用了 2 卡映射 | 同上，用 `run_siteB.sh` |
| 产物覆盖了 site A 的文件 | 漏了 `LFM_MACRO_OUT` | 同上；已覆盖的文件从 git 恢复并回报 |
| 想中途 kill 再续跑 | runner 是断点续跑的：已存在 `run_<tag>.json` 的任务自动跳过 | 直接重启同一命令即可 |
| `diagnose_expert_usage.py` 报 "no run json with router_weights" | 该 run 是 T4 之前跑的 | 用 B0 新跑的 `run_b0repro_moe_tk2_s42.json` |
| GPU 显存 61GB 撑不住 | 全表常驻 GPU 设计 | **不要改 batch_size**，回报（§8.1） |

## 十、给 AI agent 的额外要求（若 site B 由 agent 驱动）

1. **先跑 preflight，再动任何训练**；不全绿不派活。
2. **文档规范**（`AGENTS.md §1.1`）同样适用于你写的结论文档：必须有 `§0 术语定义`；禁止用"白拿""一大半"这类比喻代替定量；每个因果断言要附 `唯一变量 + 两组对照 run + 证据文件路径 + 事先冻结的判定规则` 四元组；表头必须写明端点名。
3. **每完成一个逻辑单元就 git commit**（在 `site-b/*` 分支），commit message 写清"哪个实验 / 什么变量 / 什么判定"。
4. **不要自行扩充实验矩阵**。想加配置 → 先回报，由 A 更新预注册文档后再跑。
5. **负结论同样要如实上报**。本项目的价值有一半来自"关闭错误方向"（容量路线、ID embedding 都是这样关掉的）。
