## 5. V2 相对 V1 的改进点（6 项）

V2（`main_moe_v2.py` / `DCNv2MoE_V2`）在 V1 基础上做了如下加固：

1. **新增 shared expert**：常驻、所有 token 都过（维度 `360//(K+1)`），与 K 个 routed expert 并行。
2. **Noisy Top-K Gating**：训练时给 logit 加高斯噪声、做 top-k 选择；推理时纯 top-k（无噪）。
3. **Load Balancing Loss**（Switch 风格）：防止专家坍塌，仅稀疏模式（top_k<K）计算并叠加到 BCE。
4. **Warmup→Sparsify 调度**：epoch1 `top_k=K`（软路由，等价于 vanilla）；epoch2+ 降为 `TOP_K_TARGET`（稀疏）。
5. **regime-switch 修复（2026-08-09）**：warmup 与 sparse 是两个不同路由体制，体制切换时重置 early-stop 基线并把 best 权重对应的 `top_k` 一并记录/恢复，避免"回滚到 warmup 权重却保留 sparse 路由"的错配。
6. **零额外参数量**：`CrossExpertLayerV2` 参数量 = dim_shared + K·dim_routed = dim，与 vanilla 严格相等；init 时 `top_k=K` 输出 ≡ vanilla。

> 本次实验 A 用 `--top-k-target 4`（=K=4），即**稠密路由**：epoch1 与后续均 `top_k=4`，4 个 routed + 1 个 shared **全部参与**，且不触发 regime-switch 分支（见 `main_moe_v2.py:223` 条件 `TOP_K_TARGET < K` 为假）。

## 9. 缺陷与 backlog

1. **指标混淆历史**：早期汇报用 per-scenario 平均（指标①）得出"K=2 超 baseline"，与规范 `test_auc_all`（指标②）矛盾。**今后"是否超 vanilla"一律以指标②为准**，指标①仅作逐场景诊断。
2. **单 seed 为主**：9 变体多为单 seed；K=2 d17 有 3 seed 但均 < vanilla。A/B 先 1 seed(42)，若 A 或 B 出现追平/超 vanilla 信号，扩到 42/123/456 再定。
3. **dense vs sparse 待 A 出**：V2 稠密(本次 A) 与 V2 稀疏(d6_v2=0.7709) 的直接 A/B 尚缺结果。
4. **full MoE 仅 1 例追平**：`k4_d19_v1_full_downstream=0.7777` 是唯一 ≥ vanilla 的，需 B（同 full+K4）复现确认，且需多 seed 验证稳定性。
5. **freeze 策略需固定**：rx-only 全面负迁移，但 full 训练才有追平希望——后续"MoE 有用"论证应统一用 **full 训练**，rx-only 仅作结构对照。
