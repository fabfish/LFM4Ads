## 一、目标

**这是本项目目前唯一方向一致、幅度可观的收益点**，因此需要最严格的口径审查。

问题：把预训练好的模型按场景**顺序**再训练（`0 → 1 → 2 → 3 → 4 → 5 → 6 → 8`），
base（DCNv2）会在旧场景上遗忘多少？MoE 的参数分块能否缓解？

假设：MoE 把 Cross 层切成 4 块并按场景加权，**不同场景的梯度落在不同参数块上**，
因此任务间干扰更小、遗忘更轻。

## 二、实验设置

**入口**：`python main_continual.py cuda:0`
**代码**：`train.train_continual()`（`train.py:157-217`）、`train.compute_forgetting()`（`train.py:219-241`）

| 项 | 值 |
|----|----|
| 起点 | `cache/dcnv2_vanilla.pt` / `cache/dcnv2_moe_k4.pt`（**与 Phase 1 同一份 checkpoint**） |
| 任务顺序 | `0 → 1 → 2 → 3 → 4 → 5 → 6 → 8`（**固定，仅此一种**） |
| 每个任务 | 只用该场景的 train 集训练，用该场景 valid 集 early-stop（δ=0.001，回退到最优权重） |
| 优化器 | `AdamW()` 默认参数，**每个任务重新创建**（动量/二阶矩不跨任务保留） |
| 评估 | 每完成一个任务，在**全部 8 个场景**的 test 集上评估 |
| 回放 / 正则 | **无**（无 replay、无 EWC、无 LwF）——这是最朴素的顺序微调 |
| seed / trial | 1 次 |

**产物**：`cache/continual_results.json`
（`pre_continual`、`{vanilla,moe}_trajectory`、`{vanilla,moe}_forgetting`、`final_auc`）

**起点自洽性**：核查项 C2 确认 `pre_continual` 与 `result_moe.csv` 的 16 个 AUC **逐位相等**——
两者加载的是同一份 checkpoint，因此本实验与 base-vs-MoE 文档**完全可比**。

## 三、⚠️ 口径警告：`*_forgetting` 字段不能直接当作"遗忘"

`compute_forgetting`（`train.py:219-241`）有三个必须知道的问题：

| # | 问题 | 细节 |
|---|------|------|
| **R4 / D1-C** | **符号写反（已修复）** | docstring 写 `Positive = forgetting occurred`，实现却是 `auc_current − auc_baseline`。**负值才是遗忘。** ✅ 2026-08-09 已改 docstring |
| **R5 / D1-D** | **baseline 不是预训练水平（已修复）** | `auc_baseline = results[0]`，即**训练完 task 0 之后**的 AUC ✅ 2026-08-09 已改 `pre_continual` |
| **D12（新）** | **baseline 对所有 j 都固定为 task 0** | 正确的 BWT 应比较 `a[T-1][s_j]` 与 `a[j][s_j]`（刚学完任务 j 时）。代码却统一用 `a[0][s_j]`，于是 j>0 的条目里**混进了"任务 j 自己训练带来的提升"**——这正是 28 条中有 11 条为正的原因 |

因此本文档同时报告**三套口径**，并以标准 BWT 为主要结论。
（复现：`python scripts/diagnose/analyze_continual.py`，产物 `cache/continual_analysis.json`）

## 五、结果 2：三套口径的遗忘指标

**提取**：`python scripts/diagnose/analyze_continual.py`

| 指标 | Vanilla | MoE | MoE 相对改善 |
|------|---------|-----|-------------|
| 平均 forgetting（code 口径，负=遗忘，28 条） | -0.0236 | **-0.0076** | **+67.8%** |
| 最差单条 forgetting | -0.1020 | **-0.0512** | +49.8% |
| 真实遗忘条目数 / 28 | 20 | **13** | −7 条 |
| **BWT（标准反向迁移，7 条）** | **-0.0304** | **-0.0236** | **+22.5%** |
| pre→final 未加权均值漂移 | -0.0062 | -0.0054 | +13.7% |
| **pre→final 流量加权漂移** | **-0.0144** | **-0.0084** | **+41.5%** |
| 头部场景 0+1 加权 pre→final | -0.0172 | **-0.0094** | +45.4% |
| LA（刚学完时的任务内 AUC）均值 | 0.7377 | 0.7371 | −0.0006 |

> **"MoE 遗忘降低 68%" 是 code 口径（D1-D 修复后 baseline=pre_continual）的说法，口径依赖性很强。**
> 按学术界标准的 BWT，改善只有 **22.5%**；按未加权 pre→final 只有 **13.7%**。
> 三套口径**方向完全一致（MoE 更抗遗忘）**，但幅度从 13.7% 到 67.8% 不等。
> 对外表述建议用 **BWT −0.0236 vs −0.0304**（最保守、最标准）
> 或**流量加权 −0.0084 vs −0.0144**（最贴近业务）。

### 5.3 塑性未被牺牲

LA（刚学完任务 i 时在场景 i 上的 AUC）均值：Vanilla 0.7377 vs MoE 0.7371，仅差 0.0006。
**MoE 的抗遗忘不是靠"学不进去"换来的**——这排除了"MoE 只是学习率更低/更新更少"的平凡解释。

## 六、分析

1. **抗遗忘是 MoE 目前唯一稳健的优势**。静态 AUC 上 MoE 按流量加权反而略差（−0.0071，
   见 [base-vs-MoE 文档](./20250808-1720-LFM4Ads-base-vs-MoE效果对比.md) §3.2），
   但持续学习下按流量加权改善 +41.5%，且塑性无损。
2. **改善集中在尾部风险**：4/7 任务更好，且集中在遗忘最重的场景 3 与场景 0。
   这符合"参数分块减少梯度干扰"的假说——干扰越强的地方，分块的收益越大。
3. **但机制假说尚未被直接验证**：`dcnv2_moe_k4.pt` 的 Router 熵亏损只有 **0.126%**
   （见 base-vs-MoE 文档 §五），几乎没有场景分化。
   若专家没有按场景分工，"梯度落在不同参数块"就缺少直接证据。
   目前更保守的解释是：**把一个 360×360 的稠密矩阵拆成 4 个 90×360 的块，
   本身就降低了参数间的耦合**，与路由是否分化无关。
4. **验证这条机制的实验（Phase 3 SpecializationLoss）从未真正跑过**（缺陷 D1-A/D1-B）。
   这是当前最大的空白。

## 九、踩坑

1. **符号读反会得出相反结论**：`forgetting` 字段负值才是遗忘，docstring 写的是反的。
   28×2 条全部重算核对后才敢下结论（核查项 C7）。
2. **"降低 58%" 站不住**：换成标准 BWT 只有 22.5%。
   **报告改善幅度时必须同时给出口径**，否则等于挑最好看的数字。
3. **必须查塑性**：抗遗忘指标好看时，第一反应应该是"是不是压根没学进去"。
   LA 几乎相等（0.7377 vs 0.7371）才排除了这个平凡解释。
4. **场景 8 的 pre 值是个陷阱**：MoE 的 `pre[S8] = 0.7533`（Phase 1 的异常高值），
   顺序训练后回落到 0.7738 之前一度跌到 0.5916。用 pre→final 口径时，
   这类不稳定起点会显著影响结论——这也是要看多口径的原因。
