## 一、为什么开这个新阶段（背景）

上一阶段（子任务调制交叉网格，约 290 次训练）得到决定性结构性发现：

| 变体 | 训练过程 | pooled AUC（3 种子均值） |
|---|---|---|
| 稠密基准 | 整批（每样本等权） | **0.7807** |
| 稠密基准 | 按场景（每场景等权） | 0.7666 |
| 全路由混合专家 + 冻结路由 | 按场景 | 0.7714 |
| 全路由混合专家 + 正常路由 | 按场景 | 0.7683 |
| 部分路由加共享 + 冻结路由 | 按场景 | 0.7656 |

两个关键量级：

- **按场景训练本身的代价 = -0.0140**（同一个稠密模型，仅训练过程不同）
- **混合专家在按场景约束内的最大收益 = +0.0047**（全路由+冻结 vs 同过程基准）

即：**前提的代价是收益的 3 倍。** 上一阶段所有工作都发生在这个 -0.0140 的坑里。

**本阶段唯一核心问题**：这 -0.0140 是「按场景梯度」的必然代价，还是当前实现
（场景内均值 loss 累加）的缺陷？若是后者且可修复，混合专家路线价值判断将完全不同。

## 二、根因分析（已定位到代码）

`train.py` 中 `train_moe()` 的按场景循环（约 130–159 行）：

```python
for s in tab_batch.unique():
    mask = tab_batch == s
    sub = {k: v[mask] for k, v in batch.items()}
    model(sub)
    loss = criterion(sub["logit"], sub["is_click"].float())  # 场景内均值
    loss.backward()                                          # 梯度累加
optimizer.step()
```

`criterion` 是 `BCEWithLogitsLoss()`（默认 `reduction='mean'`），所以每个场景子批量贡献的是
**该场景内的平均梯度**，与其样本数无关。累加后等价于目标函数

\[ L_{\text{当前}} = \sum_s \frac{1}{|B_s|}\sum_{i \in B_s} \ell_i \]

而 `train()` 的整批训练等价于

\[ L_{\text{整批}} = \frac{1}{|B|}\sum_{i \in B} \ell_i \]

两者仅当所有场景样本数相等时一致。KuaiRand-1K 各场景样本量差异很大，
小场景被系统性放大、大场景被压缩，而 pooled AUC 是样本加权指标 → 失配。

**修复方案**：把每个子批量的 loss 按其样本占比加权：

\[ L_{\text{加权}} = \sum_s \frac{|B_s|}{|B|}\cdot\frac{1}{|B_s|}\sum_{i \in B_s} \ell_i = L_{\text{整批}} \]

即 `loss = criterion(...) * (mask.sum() / tab_batch.numel())`。
这里**不能**使用 `len(sub)/len(batch)`：`sub` 与 `batch` 都是字典，`len()` 得到字段数而非样本数。
这样在**保留按场景独立前向反向**（子任务调制所需的按场景梯度依然可得）的同时，
使总目标严格等于整批训练目标（详见第六节不变量）。

## 六、损失语义与数值不变量

### 损失语义

```python
# train.py::scenario_loss（train_moe 与校验脚本共用同一实现）
def scenario_loss(criterion, logit, label, mask, tab_batch, loss_weighting):
    base = criterion(logit, label)          # 场景内 mean
    if loss_weighting == "sample":
        w = mask.sum().to(base.dtype) / tab_batch.numel()
        return base * w                      # 仅缩放基础 BCE
    return base                             # equal：场景内 mean，不缩放
```

- `train_moe(..., loss_weighting="equal")`：保持历史行为，产物可复现。
- `sample`：仅对**基础 BCE** 乘 `mask.sum()/tab_batch.numel()`；spec_loss（若有）在之后**加法**叠加，
  不被缩放（Stage A 不启用 spec_loss，见下）。
- **禁止组合**：`sample` + `spec_loss 启用` → 直接抛 `ValueError` 拒绝执行。
  原因：spec 项是否随样本占比缩放尚未定义，静默改变正则强度会破坏可比性。
  后续若需支持，须先在本文件定义基础损失与正则项各自的加权语义。

### 数值不变量（校验脚本 `scripts/verify/verify_scenario_loss_weighting.py`）

对同一组 logits/labels、固定模型（无随机层，DCNv2/MoE forward 均无 dropout）：

1. **损失等价**：整批 BCE mean 与「按场景 BCE mean 的样本加权和」绝对误差 ≤ 1e-6。
2. **梯度等价**：对 logits 的梯度最大绝对误差 ≤ 1e-6，相对误差 ≤ 1e-5。
3. **前向/反向一致**：固定真实小批量、模型无随机状态，`scenario_loss(..., "sample")` 与整批
   `criterion` 得到的 loss、对权重的梯度满足上述容差。
4. **equal 一致性**：`scenario_loss(..., "equal")` 等于各场景 mean 之和（即历史 `train_moe` 行为）。
5. 校验**不进入**正式训练热路径（仅 run-code `equ-swg` 触发），避免额外前向与日志开销。

任一不变量失败 → 状态只能是 DEBUG，禁止进入稠密关卡（3 种子）。

## 九、Stage A 关卡决策表（四态）

### 输入

- 已有整批稠密 3 种子均值 **0.7807**（上界参照 `swg-dens-fb-*`）。
- 已有按场景 equal 稠密 3 种子均值 **0.7666**（下界参照 `swg-dens-eq-*`）。
- 新运行按场景 sample，seed 42/123/456，读取各自 summary 的 `pooled_auc`。
- 汇总**必须**从逐 seed summary 读取，不得只抄文档均值。

定义恢复率：

\[ R=\frac{\overline{AUC}_{sample}-0.7666}{0.7807-0.7666} \]

### 决策表

| 状态 | 机械判定（全部满足才落该态） | 后续动作 |
|---|---|---|
| **PASS** | 不变量全部通过；3 个 seed 完整；sample 与 full 均值差绝对值 ≤ 0.0036；R ≥ 0.75；至少 2/3 seed 比 equal 更接近 full | 解锁第九节铺开（9 次 MoE） |
| **FAIL** | 不变量通过且产物完整，但 R ≤ 0.25，或 sample 相对 equal 的均值增益 ≤ 0.0036 | 停止旧 MoE 铺开，记录负结果 |
| **INCONCLUSIVE** | R 位于 (0.25, 0.75)，或种子方向混合且无实现异常 | 仅追加种子 789、2024 后重新判定一次 |
| **DEBUG** | 不变量/配置/依赖/写盘/NaN/OOM/随机层/optimizer.step 语义任一异常 | 修复后从冒烟重启，不得解释 AUC |

追加种子后仍不满足 PASS 或 FAIL → 保持 INCONCLUSIVE，由用户决定；禁止执行模型自行推进。

- pooled AUC 与按场景均值，**禁止只择优报告**。

只有 normal-router 稳定超过 frozen-router，才允许重新讨论旧 router 调制；否则永久关闭旧 36 配置网格。

## 十四、Stage B–F 锁定条件（未解锁前不可执行）

- **Stage B**：低秩全维专家、soft routing、同参数与同 FLOPs dense；失败则禁止 sparse scaling。
- **Stage C**：data-only / task-ID-only / data+task / consistency / frozen-uniform 路由比较
  （同时看 AUC / BWT / load / route churn / task-expert MI）。
- **Stage D**：先 shared/task-separated state × AU-only/AU+alignment 的 2×2，再扩四参数块；
  必须记录每块每任务 AU、cosine、有效步长、参数/路由漂移。
- **Stage E**：统一预训练点比较 SeqFT、EWC、Replay、Branch-Train-MiX、MoE-SeqFT、Dual-Optim、
  Dual-Optim+、完整方法；至少 3 order × 3 seed。
- **Stage F**：仅 B–E 全通过后进行 soft→top-2→top-1，与 same-active / same-total / same-latency dense 比较。
