# MoE 下游留出域参数高效迁移驱动

> 状态：`done`（G1 可行性门控失败，按协议停止，未扩 seeds 123/456）
> 授权：`authorized`（用户于 2026-08-12 明确要求「host 该实验开始执行」，已生成独立 authorization）
> G0 技术不变量与 G0-final 审计均 PASS（`cache/audit/downstream_transfer/protocol_invariants.json`，`formal_training_authorized=true`）；G1（seed 42）12/12 trial 完成但门控 FAIL。结论见 [G1 结论](../conclusions/20260813-1219-MoE下游留出域迁移G1结论.md)。

## 1. 判断与目标

现有证据不能支持“MoE 已有下游优势”，也不能据此判定“MoE 不可能有下游优势”：

1. 既有 `main_moe.py` / `main_moe_v2.py` 实际完成的是 13 个 FeatureUsage 配置，加一个不加载任何预训练参数的 `ModuleUsage(..., "Vanilla")` 随机初始化占位；没有 true MoE ModuleUsage，也没有 ModelUsage。
2. 既有 FeatureUsage 使用按用户聚合的静态 `CRs`，聚合源包含 train+validation；它不是严格的逐样本留出域迁移协议。
3. 上游静态 pooled AUC、same-FLOPs 和持续学习 screen 的负结果，只能关闭对应主张，不能替代“未见目标域标签时，MoE 专家库能否以更少可训练参数完成目标域适配”的检验。

因此新路线不再追求同分布静态 AUC，而检验一个与 MoE 结构对齐、可证伪的下游主张：

> **在目标场景标签完全不进入预训练、目标域仅给固定 4096 条标注样本、可训练参数近似匹配时，冻结的全维低秩 MoE 专家库仅适配 router+binary head，能否在固定测试集上跨训练 seed 一致优于冻结 dense backbone 的 rank-2 residual adapters+binary head。**

该主张若成立，优势定义为“留出域、低标签预算、参数高效迁移”；不外推统计总体显著性、静态总体 AUC、在线延迟、持续学习或所有 MoE。该比较只匹配下游可训练参数，不声称冻结 backbone 总参数/总容量匹配。

## 2. 为什么选择这条路线

- MoE 的合理归纳偏置是“复用多个源域专家并重新组合”，不是在同分布 pooled objective 上必然超过 dense。
- 目标域留出阻断了“预训练已见目标场景标签”的捷径。
- router-only 适配直接检验专家组合是否有用；MoE-head-only 对照可区分“专家表示好”与“路由适配有效”。
- dense rank-2 adapters 与 MoE routers 的可训练参数几乎相同，避免用额外参数制造优势。
- 使用 `DCNv2MoE_LowRank(K=4,r=45)`：每个专家输出完整 360 维；它是真正可混合的全维专家，而不是 V1 的输出通道切片。

## 3. 冻结的数据协议

### 3.1 场景

- source scenarios：`[0,1,3,4,8]`；
- held-out target scenarios：`[2,5,6]`；
- target 的 train/validation/test 行均不得进入 source pretrain；
- 非正式场景 `7/9/10/11/12/13/14` 不进入本关卡。

选择 target 2/5/6 的原因是覆盖大、中、小训练域，同时测试集正样本数分别足以稳定计算 AUC；不允许根据结果更换 target。

### 3.2 时间切分

source pretrain 沿用仓库固定切分：

- train：`date < 20220503`；
- validation：`20220503 <= date < 20220506`；
- test：`date >= 20220506`。

目标域下游的 4096 条标注预算只从 target train 时间段抽取，并预注册地按稳定 hash 排序划分为 3072 条 fit + 1024 条 validation；仓库原 target validation 不用于训练、早停或 arm 选择，仅可在完成判定后作为未参与决策的补充外部检查。target test 只在状态冻结后评估一次。

### 3.3 标签预算

- 每个 `(target, seed)` 固定抽取 4096 条 target-train 自然分布样本，其中 3072 fit、1024 validation；
- seeds：`[42,123,456]`；
- 使用稳定行索引抽样/划分并保存 fit/validation 索引 SHA-256、样本数、正负样本数；
- 同一 `(target, seed)` 的全部 arm 使用完全相同的 fit/validation 行；
- target 5 的 4096 条接近其全部 12931 条训练样本的三分之一，结论不得描述为极少样本；
- 禁止按 arm 重采样、按结果改为分层采样或扩大预算。

## 4. 上游预训练公平性

每个 seed 配对训练：

1. `dense-source`：`DCNv2(dim=360)`；
2. `moe-source`：`DCNv2MoE_LowRank(dim=360,K=4,r=45,routing=data)`。

冻结条件：

- 相同 source 行、batch order、batch size、optimizer、LR、weight decay、最大 epoch 与早停规则；
- pooled per-sample BCE，不做场景等权；
- 同 seed 两模型固定同一设备；
- 以 validation pooled AUC 选 checkpoint；
- dense 与 MoE 交叉层理论 FLOPs 对齐；参数量、实测训练/推理时间单独报告，不宣称 same-latency；
- source test 只作质量审计，不作为下游 arm 选择依据。

## 5. 下游四个 arm

所有 arm 使用逐样本即时表示，不使用用户级静态 `CRs`。

### A. `dense-head`

- 冻结 dense sparse/cross/DNN；
- 只训练新的 360→1 binary head；
- 作用：dense 表示线性探针。

### B. `dense-adapter-r2`

- 冻结 dense sparse/cross/DNN；
- 每个三层 cross 增加 bias-free rank-2 residual adapter：`360→2→360`；
- `up` 零初始化，保证初始函数等于冻结 dense；
- 训练三个 adapters + binary head；
- 可训练参数：`3 × 2 × 360 × 2 + 361 = 4681`。

### C. `moe-head`

- 冻结 MoE sparse/experts/routers/DNN；
- 只训练新的 360→1 binary head；
- 作用：MoE 表示线性探针。

### D. `moe-router`

- 冻结 MoE sparse/experts/DNN；
- 训练三个 `DataRouter(360→4)` + binary head；
- 可训练参数：`3 × (360×4+4) + 361 = 4693`。

B 与 D 相差 12 个参数（0.26%）；正式汇总必须同时报告绝对数量。不得增加 MoE-only projection、target embedding 或额外 expert。

## 6. 下游优化协议

- batch size：512；
- AdamW：`lr=5e-4`、`betas=(0.9,0.999)`、`weight_decay=0`；
- shuffle=true，DataLoader generator 由 `(seed,target,epoch)` 确定；
- max epochs：50；
- validation AUC 早停：patience=5、min_delta=`1e-4`；
- 每个 arm 从相同的 seed 派生初始化；binary head 初始化必须配对；
- 主指标：每 target test AUC；
- 次指标：macro target AUC、训练时间、推理时间、可训练参数、router entropy；
- test 不参与早停、超参选择或 arm 淘汰。

## 7. 关卡与判定

### G0：实现与证据审计

技术 G0 必须全部 PASS：

1. source/target 行互斥且样本计数守恒；
2. 4096 行及 3072/1024 划分索引在四 arm 间逐字节一致；
3. 冻结参数在训练前后 bitwise 不变；
4. dense adapter `up=0` 时与 dense-head backbone 表示一致；
5. `dense-adapter-r2` 与 `moe-router` 可训练参数差不超过 1%；
6. 同 seed 所有配对 arm 固定同卡；
7. source/model/runner/driver 的 SHA-256 冻结；
8. 独立产物目录且不可覆盖。

顺序固定为：技术 G0 PASS → 生成并冻结独立 authorization（含 G0 report hash）→ G0-final 校验 authorization/hash/设备映射 → 才允许 G1。任一步失败，矩阵为 `blocked`。

### G1：seed 42 feasibility gate

先完成 target 2/5/6 的四 arm。只有同时满足以下条件才允许 seed 123/456：

- 三个 target 的 validation `moe-router - dense-adapter-r2` 均 `>0`；
- 三个 target 的 validation `moe-router - moe-head` 均 `>0`；
- 无冻结、样本、设备或 hash 异常。

G1 只控制是否扩矩阵，不产生正式优势结论；失败即停止，不扫描 LR/K/r/target。

### G2：正式优势 gate

主比较为同 seed、同 target 的：

`Δ_primary = AUC(moe-router) - AUC(dense-adapter-r2)`。

同时计算机制归因差分：

`Δ_adaptation = (AUC(moe-router)-AUC(moe-head)) - (AUC(dense-adapter-r2)-AUC(dense-head))`。

判定规则预注册为：

- **PASS**：9/9 个 `Δ_primary > 0`；每个 target 的 3-seed mean `Δ_primary >=0.001`；macro 9-pair mean `Δ_primary >=0.0015`；9-pair mean `Δ_adaptation >=0.0005`；且每个 target 的 `Δ_adaptation` 3-seed mean `>0`。
- **FAIL**：9/9 个 `Δ_primary <=0`，或三个 target 的 mean `Δ_primary` 全部 `<=0`。
- **INCONCLUSIVE**：其余方向混合、虽为正但未达到实际显著性阈值、或 `Δ_adaptation` 未满足归因规则。
- **BLOCKED**：缺 trial、训练失败、测试泄漏、设备混杂、参数不匹配、冻结变化、hash/样本审计失败。

不得用 macro 均值覆盖某 target 的系统性退化，不得从多个 budget/target/层中事后挑最好结果。这里的“稳定”只指固定 test 样本上跨训练 seed 方向一致；target 5 test 仅 1833 条，不宣称总体统计显著性。可附 paired bootstrap CI 作为描述性不确定性分析，但不改变上述 gate。

## 8. 结论模板

若 PASS，只允许表述：

> 在 KuaiRand-1K 固定 source `[0,1,3,4,8]`、held-out targets `[2,5,6]`、4096 总标注（3072 fit + 1024 validation）、3 个训练 seeds、约 4.7k 下游可训练参数的协议下，low-rank full-dimensional MoE 的 router-only 适配在固定测试集上方向一致地优于 dense rank-2 adapter，且适配增益双重差分为正，支持该协议下的留出域参数高效迁移优势。

不得表述为：

- MoE 普遍优于 dense；
- MoE 静态 pooled AUC 更高；
- MoE 推理更快；
- 已解决持续学习或灾难性遗忘；
- 可外推到其他数据集、K/r 或更大规模。
