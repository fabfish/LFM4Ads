## 一、要回答的问题

已有 12-run 矩阵的结论边界是：**capacity MoE 的 router 特化机制成立（12/12 哨兵 PASS），但 test AUC 只微弱正向（+0.0002~+0.0025），未达显著。**

但该结论有一个**未被剥离的混淆项**：

> 现有 Δ = "MoE 训练后 test AUC" − "冻结 dense 参照 test AUC"。这个 Δ 里混入了
> **"继续训练"本身的红利**——dense 参照是只 evaluate 不训练的，而 MoE 多训了 7~10 个 epoch。
> 所以 +0.0025 到底是"MoE 结构带来"，还是"多训几个 epoch 带来"，现有数据无法分辨。

**本阶段要回答的唯一前置问题**：在剥离"继续训练红利"之后（即与"同样继续训练的 dense"对比），
capacity MoE 是否仍有必要——也就是 **配对差 Δ_necessity = MoE_best − dense_cont_best** 是否仍为正且越过噪声地板。

### 1.1 一个必须显式暴露的风险信号（来自 smoke 日志）

重读最优候选（`s42_k2_w2_lb1e3`，top_k=2）的逐 epoch valid AUC 轨迹，发现：

| epoch | phase | top_k | valid AUC | entropy_mean |
|---|---|---|---|---|
| 1 | warmup | 4 | 0.7789 | 1.2282 |
| 2 | warmup | 4 | 0.7757 | 1.1044 |
| 3 | sparse | 2 | 0.7606 | 1.1746 |
| 4 | sparse | 2 | 0.7481 | 1.1200 |
| 5 | sparse | 2 | 0.7371 | 1.0623 |
| 6 | sparse | 2 | 0.7261 | 1.0118 |
| 7 | sparse | 2 | 0.7185 | 0.9743 |

**sparse 阶段 valid AUC 单调下降**（0.7606 → 0.7185），test AUC=0.78 实际上取自 warmup 的
best state（epoch 1）。也就是说：

- 报告里的 "+0.0025" **来自 warmup（软路由 top_k=4、全专家激活）阶段，不是来自稀疏 dispatch**。
- **稀疏化之后模型反而持续变差**，一路跌破 dense（0.7775）。

这意味着"MoE 改变必要性"在当前证据下处于**危险的模糊地带**：机制通了，但"容量收益"只在
warmup 阶段兑现，一旦真正稀疏化就回吐。本阶段必须把这件事测清楚，而不是含糊地说"微弱正向"。

### 1.2 本阶段判定的是"必要性"，不是"显著性"

本阶段只回答**方向性问题**：剥离继续训练红利后，MoE 是否仍不劣于（最好优于）dense-continued。
显著性的正式判定（3-seed 矩阵 + 统计检验）留给后续关卡。2 seed 快验证结论只能作为
"必要性成立 / 不成立 / 存疑"的**方向证据**，不能作为"显著优于"的高置信结论。

## 二、三臂定义（冻结）

| 臂 | 变体 | 训练动作 | 用途 |
|---|---|---|---|
| A | **dense 冻结参照** | `DCNv2`（`cache/dcnv2_vanilla.pt`），只 evaluate 不训练 | 与 smoke 口径对齐的历史锚点 |
| A′ | **dense-continued** | `DCNv2` 从同一 ckpt **继续训练 16 epoch**（同 optimizer/lr/loader/样本加权） | 剥离"继续训练红利"的公平基线 |
| B | **MoE-optimal** | `DCNv2CapacityMoE`，upcycle 后 warmup 2 + sparse 训练 16 epoch | 被测项 |

- 三臂共享：`dim=360`、`K=4`、`embed_dim=10`、dense 预训练 ckpt 完全一致（`cache/dcnv2_vanilla.pt`）。
- **必要性主指标**：`Δ_necessity = B_test_best − A′_test_best`（逐 seed 配对，同卡）。
- 次要参照：`Δ_smoke = B_test_best − A_test`（仅用于与 smoke 口径对照，不进入判定）。
- A′ 与 B 的训练协议**逐字段一致**，唯一差异是被测结构（dense vs capacity MoE）本身，见 §三/§四。

## 三、冻结协议（快验证阶段）

### 3.1 共同超参（A′ 与 B 完全一致）

| 项 | 值 |
|---|---|
| lr | `1e-3` |
| optimizer | `AdamW(betas=(0.9, 0.999))` |
| batch_size | `10000` |
| num_workers | `10` |
| loss 加权 | `sample`（`train.scenario_loss`，per-scenario 子批 + 样本比例加权） |
| max_epochs | `16` |
| min_epochs | `16`（**强制跑满 16 epoch、关闭 early-stop**，以获取完整 sparse 轨迹判断"收敛还是持续崩溃"） |
| 数据切分 | `dataset.Split`（date < 20220503 / 20220503–20220506 / ≥ 20220506） |

> 说明：smoke 用 `min_epochs=1` + early-stop，导致 sparse 阶段只跑到 epoch 7 就被截断，
> 无法判断缓降是"过渡态"还是"持续崩溃"。本阶段 `min_epochs=16` 强制跑满，直接回答 §1.1 的风险。

### 3.2 臂 B（MoE-optimal）专属超参（冻结，与 12-run 最优候选一致）

| 项 | 值 |
|---|---|
| K | `4` |
| top_k | `2`（12-run 中一致优于 top_k=1） |
| noise_scale（upcycle 乘法扰动） | `0.1` |
| lb_alpha（load-balance 系数） | `0.001` |
| warmup_epochs | `2` |

### 3.3 臂 A′（dense-continued）训练协议（冻结）

- 从 `cache/dcnv2_vanilla.pt` 加载 `DCNv2`，**不 upcycle、不加 lb loss**。
- 训练循环结构与臂 B **完全一致**：per-scenario 子批 forward + `scenario_loss(..., "sample")` + 单次
  `optimizer.step()` per batch；仅删去 MoE 的 `_load_balance_loss` 项（dense 无 router，无法产生该项）。
- 逐 epoch 记录 valid AUC，best state 的 test AUC 作为 `A′_test_best`。
- **计算量口径声明（保守）**：dense-continued 每 epoch FLOPs ≈ 1 个交叉层；MoE warmup 阶段每 epoch
  算了 K=4 倍专家 FLOPs。本阶段**不折抵 warmup 的 K 倍 FLOPs**——即 A′ 在"每 epoch 算力"上反而吃亏，
  该口径**偏袒 dense**；若 Δ_necessity 仍为正，则必要性成立是**保守成立**。

### 3.4 并行分配（遵守 AGENTS.md 同 seed 同卡规则）

| 卡 | seed | 串行跑的臂（同卡，避免显存竞争） |
|---|---|---|
| `cuda:0` | 42 | A′ dense-continued(16ep) → B MoE-optimal(16ep) |
| `cuda:1` | 123 | A′ dense-continued(16ep) → B MoE-optimal(16ep) |

- 同一 seed 的 A′ 与 B **跑在同一张卡**（配对差不引入设备混杂因子）。
- 不同 seed 分布到不同卡并发。
- 每卡先跑 A′ 再跑 B，串行避免显存竞争。

## 四、审计五步（启动前核对）

### §1 样本计数守恒

- 训练按场景切子批，各场景子批样本数之和 == 整批样本数（不重复、不漏），由 `train.scenario_loss`
  + `main_moe_capacity.py` 既有实现保证。臂 A′ 复用同一 `scenario_loss` 路径，守恒性一致。
- 判定：复用既有实现 = PASS；若臂 A′ 新增代码改动切分逻辑，须打印每 epoch 总样本数核对。

### §2 配对口径（控制变量）

- A′ 与 B 除被测结构外，seed / lr / batch_size / beta2 / device / loss_weighting / epoch 数 / 数据切分
  **逐字段一致**（见 §3.1）。
- **禁止**用跨 seed 均值差冒充"匹配/等价"；必须报逐 seed 配对差并标注是否跨 seed 变号。

### §3 路由器语义

- 本阶段**不冻结任何路由器**（臂 B 的 router 全程可训练），故"冻结=零噪声"条款不适用。
- 臂 B 的 upcycle 用非零小随机 init（`router.weight ~ N(0, 0.01)`），已在 smoke 驱动 §3.2 冻结，不重复校验。

### §4 恢复率 R 数学

- 本阶段不涉及 sample-weighted vs full-batch 的恢复率计算（那是 Stage A 的指标），跳过。

### §5 结论边界登记

见 §六，每条结论登记 {claim, evidence, 判定, 可降级为}，启动后不得改判更弱。

## 五、哨兵指标（冻结，判定唯一依据）

### 5.1 必要性配对差 Δ_necessity（主哨兵）

```
Δ_necessity[seed] = B_test_best[seed] − A′_test_best[seed]
```

- 逐 seed 计算，必须同卡配对。
- 噪声地板：**`|Δ| > 0.001`**（与 smoke 阶段最优候选的 Δ 量级一致，且接近历史 dense 3-seed 极差 0.0017）。
- 保护指标：报告 A′ 臂自身的 2-seed 极差 `|A′[42] − A′[123]|` 作为经验噪声地板；若 `|Δ|` 小于该极差，
  则 "stable improvement" 判据不满足（降级为 INCONCLUSIVE）。

### 5.2 router 特化（沿用 smoke 哨兵）

- 末 epoch（epoch 16）三层 clean-gate 熵均值 `entropy_mean ≤ log K − 0.15 = 1.2363`。
- 逐层熵一并报告（保护指标）。

### 5.3 真实稀疏 dispatch（沿用 smoke 哨兵）

- 每层实际执行前向的专家数 == `top_k=2`（未选中专家前向不执行），由 `routing_sentinel` 的
  `dispatch_verified` 校验。

### 5.4 sparse 阶段 AUC 轨迹（本阶段新增的关键哨兵）

- 观察 sparse 阶段（epoch ≥ 3）valid AUC 的**单调性**：
  - **企稳/回升**（末段 epoch 不再逐 epoch 下降）→ 支持"缓降只是过渡态，更长训练有利"。
  - **持续单调崩溃**（valid AUC 逐 epoch 下降且末 epoch 明显低于 dense-continued 同 epoch）→
    支持"稀疏化本身在伤害模型"，必要性存疑。

## 六、判定规则（预注册，事后不得降级）

verdict ∈ `{PASS, FAIL, INCONCLUSIVE}`，规则冻结如下：

| 条件 | verdict |
|---|---|
| 前向/反向不崩 **且** dispatch 真实稀疏（§5.3） **且** 2 seed 的 Δ_necessity **均 > +0.001 且同号** **且** 末 epoch 熵 ≤ 1.2363（§5.2） | **PASS**（必要性保守成立：即便偏袒 dense 的口径下 MoE 仍胜出） |
| 前向/反向崩溃，或 dispatch 未生效（实际执行专家数 != top_k） | **FAIL**（机制破坏） |
| 机制生效（dispatch+熵 PASS）但 Δ_necessity 未同时满足"2 seed 同号且 >0.001"（含跨 seed 变号、或 ≤0.001、或 2 seed 均 < 0 但机制正常） | **INCONCLUSIVE**（必要性未证明；登记具体缺口：是"变号"还是"幅度不足"还是"稳定为负"） |

补充登记规则（不让结论糊过去）：

- 若 **2 seed Δ_necessity 均为负**（MoE 稳定劣于 dense-continued），判定为 **INCONCLUSIVE 且方向为负**，
  结论文档必须显式写"必要性**不成立**（在偏袒 dense 的口径下仍更差）"，不得写成"微弱正向"。
- 若 sparse 轨迹 §5.4 判定为"持续崩溃"，即使 Δ_necessity 靠 warmup best 撑到正，也必须在结论中
  **单列一行**声明"+Δ 来自 warmup 阶段，稀疏化后回吐"，不得把 warmup 红利算作稀疏 MoE 的收益。

**禁止事项**：
- 不得事后把 0.001 的噪声地板下调。
- 不得用 `Δ_smoke`（对冻结 dense 的差）冒充 `Δ_necessity`（对 dense-continued 的差）。
- 不得把 warmup 阶段（top_k=K、全专家激活）的 best state 说成"稀疏 dispatch 的收益"。
- 不得用跨 seed 均值差下"显著优于"的结论。
