# GPU0 占位守护（fake load keeper）

日期：2026-08-12
主题：后台长驻守护，空闲后置位 10% 假负载，真实任务来了让位

## 目标
在 GPU0 空闲足够久后，启动一个只占 ~10% GPU 利用率的“假计算程序”，保持卡处于被占用状态（避免被调度器/集群回收）；一旦有真实 GPU 任务挂上，立刻停掉假程序让位。

## 实现
- `scripts/gpu_keeper.py`：主程序。默认以“监控态”运行，用 `nvidia-smi` 轮询 GPU0 的计算进程与利用率（监控主进程不依赖 torch，轻量）。需要假负载时，`subprocess` 拉起自身 `--fake` 子进程，子进程用 torch 做小矩阵乘，以 10% 占空比循环。
- `scripts/start_gpu_keeper.sh` / `scripts/stop_gpu_keeper.sh`：长驻后台启动/停止（基于 `setsid nohup`，退出 shell 不中断）。
- `scripts/gpu-keeper.service`：systemd 单元（当前机器无 systemd，留作在 systemd 主机上使用）。

## 行为（默认）
1. GPU0 连续空闲（`IDLE_THRESHOLD_S`，默认 1200s=20min）无真实计算进程 → 启动假程序。
2. 假程序运行 `FAKE_DURATION_S`（默认 1200s=20min；设 0 = 一直跑到真任务出现）。
3. 假程序运行期间，若 GPU0 出现“其他”计算进程（真实任务）→ 立即终止假程序并让位。

## 配置（环境变量，可选）
| 变量 | 默认 | 含义 |
|---|---|---|
| `GK_GPU_ID` | 0 | 物理 GPU 序号 |
| `GK_TRIGGER` | idle | idle=空闲这么久后启动；busy=被真实任务占用这么久后启动 |
| `GK_IDLE_THRESHOLD_S` | 1200 | 空闲/占用判定时长（秒） |
| `GK_FAKE_DURATION_S` | 1200 | 假程序时长（秒）；0=跑到真任务出现 |
| `GK_POLL_S` | 10 | 轮询间隔（秒） |
| `GK_HOLD_MEMORY_MB` | 2048 | 占位显存大小（MiB） |
| `GK_TARGET_UTIL` | 25 | 目标 GPU 利用率（%，实测略低于标称，确保计算核 >=20%） |

> 注意：本机 `nvidia-smi` 序号与 torch `cuda:{id}` 默认一致（均未设 `CUDA_VISIBLE_DEVICES`）。若设了该变量需自行核对映射。

## 启动方式
```bash
# 长驻后台（无 systemd 时）
bash scripts/start_gpu_keeper.sh
# 调参示例：空闲 5 分钟即启动、假程序一直跑到真任务出现
GK_IDLE_THRESHOLD_S=300 GK_FAKE_DURATION_S=0 bash scripts/start_gpu_keeper.sh
# 查看日志
tail -f logs/gpu_keeper.log
# 停止
bash scripts/stop_gpu_keeper.sh
```

## 重启自愈（可选）
当前机器无 systemd，但有 `crond`。如需开机/重启后自动拉起，可加 `@reboot` 任务到用户 crontab：
```cron
@reboot sleep 30 && cd /root/Documents/Lfm4ads && setsid nohup python3 scripts/gpu_keeper.py >> logs/gpu_keeper.log 2>&1 &
```
（集群节点上 `@reboot` 是否生效取决于 crond 是否随节点启动；更稳妥的是放进节点的开机脚本。）

## 验证（2026-08-12 冒烟）
- 用小阈值跑监控：空闲 3s 后成功启动假程序（pid 正确）。期间 GPU0 出现一个瞬态计算进程，守护立即识别并让位停止 → “真任务来了就停”逻辑成立。
- 单独跑 `--fake` 12 秒：GPU0 利用率稳定采样 9% / 9% / 9% / 11% / 10% / 9%，符合 ~10% 目标；`kill` 后可正常退出，无残留。
- 清理后：GPU0 回到 0% / 0 MiB，无 compute-apps，无 `gpu_keeper` 进程。

## 后续 backlog
- 若需要“持续占位防回收”，将 `GK_FAKE_DURATION_S=0`（假程序一直跑到真任务出现），而非默认 20 分钟。
- 多卡可在 `GK_GPU_ID` 分别起多个实例。
- 若迁移到 systemd 主机，用 `scripts/gpu-keeper.service`（`systemctl --user enable --now gpu-keeper`）。

## 重要修复（2026-08-12 下午）
- 发现根因：本机是**容器环境**，nvidia-smi 报告的计算进程 pid（GPU 命名空间，如 3369420）与 Python 子进程 pid（宿主机命名空间，如 78094）**不一致**。`is_busy(exclude=(_fake_proc.pid,))` 用宿主 pid 去排除，永远排除不掉自己的假程序，于是守护进程把假程序误判为“真实任务”→ 一启动就立即让位，从没真正跑满过。这正是最初“为什么不自动运行”的真因。
- 修复方式：启动假程序时**差分抓取**它在 nvidia-smi 中暴露的真实 GPU pid（`capture_fake_pids`，比较启动前后 compute-apps 差集），检测“真实任务”时只排除这个集合（`real_tasks()` / `excluded_pids()`）。停止后留 10s 宽限避免残影误判。
- 新增 `GK_REST_S`（冷却间隔，默认 1200s=20min）：每轮假程序跑满后歇 20 分钟再下一轮，与空闲阈值解耦。
- 当前默认行为：GPU0 空闲 **1 分钟** → 100% 假程序 **20 分钟** → 歇 **20 分钟** → 重复；真任务来了立即让位。

## 更新（2026-08-16）：满负荷 100% → 计算核 25%，消除「伤卡」

**问题**：原默认 `GK_TARGET_UTIL=100` 使假程序 `duty=1.0`、`sleep_t=0`，从不停歇地跑 4096×4096 矩阵乘，
实测 **利用率 99% / 功耗 391W / 温度 53℃**（对比 GPU1 待机 0% / 72W / 30℃），长时间满负荷确实伤卡。

**方案**：占卡改为「显存 + 低计算核」双保险，并保留可调。
- `fake_worker` 先分配 `GK_HOLD_MEMORY_MB`（默认 2048 MiB）显存并持有引用，nvidia-smi 进程表可见。
- `GK_TARGET_UTIL <= 0`：纯显存占位，计算核空闲（功耗≈待机）。
- `GK_TARGET_UTIL > 0`（默认 25）：以该占空比做小矩阵乘「心跳」，维持计算核利用率。
  - 默认 25 是因为 `time.sleep` 与 Python 循环开销造成系统性偏低，实测 25% 标称≈25% 实际，确保 ≥20%。
- cron 看门狗（每分钟 + @reboot）无需改动，自动拉起新代码守护。

**验证（2026-08-16 单进程 smoke，GPU0）**：

| 指标 | 旧版 100% | 新版 25% 标称 |
|---|---|---|
| utilization.gpu | 99% | 25% |
| 功耗 | 391W | 198W |
| 温度 | 53℃ | 37℃ |
| 显存 | 683 MiB | 2785 MiB（2048 占位 + torch 上下文） |

真任务挂上仍立即让位（`real_tasks()` 逻辑未变）。

## 停用（2026-08-19）：政策更新，弃用占卡脚本，改用真实任务

**政策**：之后不能用「假负载/占卡脚本」这类简单占位程序跑在 GPU 上；GPU 占用只能来自**真实任务**（真实的训练/评估实验）。

**处置**：
- 停掉所有 `gpu_keeper` 进程（gpu0 / gpu1 的监控主进程与 `--fake` 占位子进程），GPU 已回空闲（0% / 0 MiB / ~74W）。
- 移除 cron 看门狗：删除 crontab 中 4 条 gpu_keeper 相关条目（2 条 `@reboot` + 2 条每分钟 `start_gpu_keeper.sh`），仅保留 `PATH` 行。
- 清理 `logs/gpu_keeper*.pid` 残留 pidfile。
- `scripts/gpu_keeper.py` / `start_gpu_keeper.sh` / `stop_gpu_keeper.sh` / `gpu_keeper_uptime.py` / `gpu-keeper.service` 等文件保留在仓库作历史归档，但**不再运行**。

**后续约定**：GPU 只跑真实实验任务，空闲即空闲（不再人为占卡）；如集群有回收压力，以真实任务队列自然填充。
