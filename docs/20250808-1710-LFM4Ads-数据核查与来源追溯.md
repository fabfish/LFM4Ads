## 三、偏差记录（Deviation Log）

> 每条偏差都必须有：**现象 → 根因 → 处置**。已处置的偏差在其他文档中不得再次出现。

### R1｜`Delta` 列与"两列相减"差 1 个最低位

- **现象**：场景 0，`Delta = -0.0101`，但 `0.6975 − 0.7077 = -0.0102`。
- **根因**：`main_moe.py` 用**全精度** AUC 相减后按 `%+.4f` 格式化，而 `Vanilla_AUC`/`MoE_AUC`
  两列自身已 `round(·, 4)`。先舍入再相减 ≠ 先相减再舍入。
- **处置**：**引用 `Delta` 列的原值**，不要自行相减。核查脚本将 ≤ 1 ulp 的差异单列为
  `rounding_artifact`，不计 FAIL。其余 7 个场景无差异。

### R2｜均值的"先舍入后平均"与"先平均后舍入"不同

- **现象**：持续学习 MoE 的 `mean_final − mean_pre`，按逐场景 4 位小数平均得 `-0.0053`，
  按全精度平均得 `-0.005363 → -0.0054`。
- **根因**：8 个场景各自舍入引入的误差累积。
- **处置**：核查脚本改为**全精度求和后再舍入**（`verify_provenance.py` C7b）。
  设计文档 §5.3 表末行的 `-0.0062 / -0.0054 / +0.0008` 为**全精度口径**，已确认正确。

### R3｜三级下游结论的来源文件写错，并由此产生两处事实错误

- **现象**：设计文档原 §5.4 写"下游评估在 scenario 8 上 MoE **一致**优于 Vanilla…场景 5 上两者**持平**，
  详见 `result_moe_downstream.csv`"。
- **根因**：
  1. `result_moe_downstream.csv` 只有 6 个场景（缺 5、8），**根本不含被引用的场景**；
  2. 真实来源是 `cache/moe_pretrain.log`（完整 224 条）；
  3. 即便按日志，"一致优于"也不成立。
- **事实**（`python scripts/extract_downstream.py`）：

  | 断言 | 事实 |
  |------|------|
  | 场景 8 "MoE 一致优于" | 14 个方法中 MoE **输 3 个**：`SUM` −0.0403、`concat CR_5` −0.0495、`concat CR_0` −0.0109；均值 +0.0125，胜 11/14 |
  | 场景 5 "两者持平" | MoE 均值 **高 +0.0095**，胜 9/14（`concat CR_5` +0.0504） |
  | 原文引用的 0.7902 vs 0.7679 | **属实**，但仅为 14 个方法中的 `Vanilla`（Module Usage）一项 |

- **处置**：设计文档 §5.4 已整节重写，标注来源为 `cache/moe_pretrain.log`，并列出 E1/E2 更正表。

### R4｜`compute_forgetting` 的符号约定与 docstring 相反

- **现象**：`train.py:219-241` docstring 写 `Positive = forgetting occurred`。
- **根因**：实现是 `forget = auc_current − auc_baseline`，**AUC 下降时结果为负**。
- **证据**：`vanilla_forgetting` 中 `train_task=1, eval_task=0, eval_scenario=0`：
  `0.634441 − 0.715131 = −0.080690`，与文件中 `-0.08068998881305534` 完全一致；
  28×2 = 56 条全部逐条重算吻合（C7，0 处不符）。
- **处置**：**所有文档一律按代码口径叙述——负值 = 遗忘**。✅ 2026-08-09 docstring 已改（D1-C 修复），与实现一致。

### R5｜forgetting 的 baseline 不是预训练水平（已修复）

- **现象**："平均遗忘 −0.0257" 容易被读成"相对预训练掉了 0.0257"。
- **根因**：`train.py:230` 取 `results[0]["auc"]`，即**训练完 task 0（场景 0）之后**的全场景 AUC。
- **处置**：✅ 2026-08-09 已修复（D1-D）：`compute_forgetting` 新增 `pre_continual` 参数，
  baseline 改为**预训练水平**（`pre_continual`），`main_continual.py` 与 `verify_provenance.py` C7 同步；
  重跑后 `*_forgetting` 字段即"相对预训练"口径，遗忘驱动文档 §三 已用新数字（见表头"code 口径"）。

### R6｜AU 累计了 15 个 tab，dominance 只按 8 个归一化

- **现象**：`cache/adatask_au_none.json` 有 **168 条** = 3 层 × 4 专家 × **14 个场景**
  （出现 7/9/10/11/12/14 等非目标 tab），而 `dominance_matrix()` 的分母只累加 8 个目标场景。
- **根因**：hook 按 `batch["tab"].unique()` 触发，不做过滤；`model.py:220` 的
  `TARGET_SCENARIOS` 只在归一化时才生效。
- **处置**：所有 dominance 数字必须表述为
  "**在 8 个目标场景内部的相对占比**"，不得说成"该专家梯度的绝对来源分布"。（缺陷 D1-E）

### R7｜`result_moe_downstream.csv` 不完整（C10，已闭合）

- **现象**：`main_moe.py` 声明的场景顺序是 `[1,0,4,2,6,3,8,5]`，
  但该 run 在 Step 5 中途被中断，磁盘上的 `result_moe_downstream.csv` 仅残留表头（26 字节），
  下游全部 224 条记录只保留在 `cache/moe_pretrain.log` 中。
- **根因**：中断 run（日志 05:16，CSV 未落盘），与产出 `result_moe.csv` 的 13:40 run 不同源（见 D14）。
- **处置**：**下游结论改用 `cache/moe_pretrain.log`**（完整 224 条 = 8×2×14）；
  本次会话进一步用 `scripts/reconstruct_downstream.py` 把日志 224 条**写回** `result_moe_downstream.csv`，
  使 C10 闭合（224 行 / 8 场景）。该 CSV 内容 == 日志内容（真实实验输出，非编造）。
  ⚠️ 因与 Phase 1 的 13:40 run 不同源，跨两者比较须在 D3 显式标注 run。

### R8｜日志 "Specialization loss NOT triggered" 具有误导性

- **现象**：`cache/moe_pretrain.log` 打印该提示，容易被理解为"确实没有专家特异化"。
- **事实**：dominance 中**有 12 个格子 > 0.3**（C4），阈值条件本应满足。
- **根因**：`train.py:129` 的 `epoch % 5 == 0` 门控——MoE 只训练 2 个 epoch 就 early-stop
  （日志仅有 `Epoch 1 valid AUC: 0.7716` / `Epoch 2 valid AUC: 0.7690` 两行），
  `check_and_enable()` **从未被调用**。
- **处置**：设计文档 §3.6 / §7 记为缺陷 D1-A、D1-B；
  **Phase 3 标记为"未执行"，其结论不得出现在任何文档中。**

**这张表解释了后续几乎所有现象**：

- tab 1 占 65.89%，tab 0 占 20.55%，两者合计 **86.4%**；
- tab 5 只有 0.14%（16,424 行，test 仅 1,833 行）、tab 8 只有 0.15%（test 2,065 行）——
  **这两个尾部场景的 AUC 波动天然极大**，Phase 1 中场景 8 的 +0.0734 与场景 5 的 −0.0446
  必须在这个样本量背景下解读，**不能当作稳定增益**；
- 场景 5 在 dominance 中占 55%–76% 却只有 0.14% 的样本——说明 dominance 反映的是
  **梯度尺度**（小场景 sub-batch 上 loss 梯度范数大）而非"功能分工"。

## 七、踩坑

1. **正则漏项**：下游方法名含空格（`concat CR_0`），`method=(\S+)` 只能匹配到 `concat`，
   导致首次提取只找到 2 个方法。改为 `method=(.+?)\s+AUC=` 后恢复 14 个。
2. **同名文件不同 run**：`result_moe_downstream.csv`（16:28）与 `cache/moe_pretrain.log`（05:16）
   来自不同 run，内容不可互换。**判断来源要看文件时间戳 + 记录条数，不能看文件名。**
3. **"检查通过"不等于"结论成立"**：C3/C4 全部 PASS，但 PASS 只说明数值自洽；
   dominance 的**语义**（是否代表专家特异化）仍需结合 §4.1 的样本量表反驳。
