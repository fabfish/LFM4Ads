## 一、要回答的问题

仓库从 V1 到 SharedResidual 的所有 MoE 变体，都是「零参数切片 / 同 FLOPs / 低秩 r=45」形态，
**从未实现过 capacity-scale MoE**——即「用 K× 总参数、稀疏路由只激活 1×，在激活成本不变下塞进更多容量」。

已有 6 条路线全部失败（router 熵始终 ≈ log K、task-expert MI ≈ 0.0018），但那些实验证伪的是
「被砍容量的 MoE」，不是 MoE 本身。因为 MoE 的表达能力**严格包含** dense（router 退化为均匀 + 专家
权重相同时即精确等于 dense），被砍容量的 MoE 在表达力上必然 ≤ dense。

本阶段要回答的**唯一前置问题**：实现第一个「同激活、K× 总容量」的 full-rank 专家 + 真实 top-k
稀疏 dispatch 的 MoE 后，**router 熵能否离开 log K**——这是「路由机制终于开始工作」的第一个可验证信号。

> 关键判断：之前的失败有一个共性根因——upcycling 用「严格函数保持 + zero-specialist」锁死了专家对称性，
> 使 router 永远 uniform、熵永远卡在 log K。本次明确放弃函数保持，换取「路由可特化」。

## 三、模型定义（冻结）

### 3.1 `CapacityCrossExpertLayer`

- K 个 **full-rank** `nn.Linear(dim, dim)` 专家（每个专家参数 = dense 交叉层参数，总容量 K×）。
- data-driven router：`nn.Linear(dim, K)`，weight 用 `nn.init.normal_(std=0.01)`，bias 零。
- **真实 top-k sparse dispatch**：只对被 top-k 选中的专家做前向（按专家 index 分组 gather），
  scatter-add 得到 `[B, dim]` 加权和；未选中专家的前向**完全不执行**（区别于 V2 的
  `expert_outs=[expert(x) for expert in self.experts]` 全算后置零）。
- 输出公式保持 DCNv2 cross：`out = weighted * x0 + x`。
- 返回 `(out, clean_gate, lb_loss)`：`clean_gate` 是全 K 维 softmax（用于熵哨兵），
  `lb_loss` 是 Switch Transformer 风格 load-balance loss。

### 3.2 upcycling（打破对称性，放弃严格函数保持）

- 每个专家权重 = dense 权重副本 + **乘法扰动**：
  `expert.weight = w * (1 + noise_scale * randn)`，`expert.bias = b + noise_scale * randn`。
  `noise_scale` 默认 `0.01`。
- router 用非零小随机 init（`std=0.01`），打破「恒 uniform」。
- **代价（显式声明）**：初始 AUC 略低于 dense（不再是严格函数保持）。这是换取「路由可特化」的必要取舍。
  本阶段**不**以「初始 AUC == dense」作为任何判定依据。

### 3.3 `DCNv2CapacityMoE`

- `Sparse` + 3×`CapacityCrossExpertLayer` + 2×DNN(`Linear(dim,dim)`) + `head(Linear(dim,15))`。
- `embed`/`forward` 与现有类对齐：写 `batch["logit"]`、`batch["_gate"]`（3 层 clean gate）、
  `batch["_load_balance_loss"]`（3 层 lb 之和）。
- `upcycle_from_dense(dense)`：复制 Sparse/DNN/Head + 对 3 个交叉层做 §3.2 upcycling。
- `set_top_k(k)` 控制稀疏度。

## 五、哨兵指标（冻结，判定唯一依据）

### 5.1 clean gate 熵

对每层 router 输出的**全 K 维 softmax**（非 top-k 截断后的 gate），在 test set 上按样本平均：

```
H = mean over samples of ( -Σ_k p_k log p_k )
```

- `log K = log 4 = 1.3863`（均匀路由的熵上限，即「路由死亡」哨兵值）。
- 三层的熵取均值作为主哨兵；逐层值作为保护指标一并报告。

### 5.2 per-scenario dispatch 分化度

对每层统计「全局 argmax 专家」与「各场景 argmax 专家」；分化度 = 存在至少一个场景，其
argmax 专家 ≠ 全局 argmax 专家的层数占比（0/3 ~ 3/3）。

### 5.3 真实稀疏 dispatch 生效

统计每层**实际执行前向的专家数**（应恒 == top_k，而非 K）与 dispatch 计数分布，证明稀疏计算
真的发生（未选中专家前向不执行）。

## 六、判定规则（预注册，事后不得降级）

smoke 的 verdict ∈ `{PASS, FAIL, INCONCLUSIVE}`，规则冻结如下：

| 条件 | verdict |
|---|---|
| 前向/反向不崩 **且** 真实稀疏 dispatch 生效（实际执行专家数 == top_k） **且** 三层熵均值从 ≈log K 降至 **≤ log K − 0.15**（即 ≤ 1.2363） **且** per-scenario 分化度 ≥ 1/3 | **PASS** |
| 前向/反向崩溃，或稀疏 dispatch 未生效（实际执行专家数 != top_k） | **FAIL** |
| 不崩、稀疏生效，但熵下降 **< 0.15 nats** 或分化度 = 0/3 | **INCONCLUSIVE** |

- `PASS` → 路由机制确认工作，授权进入三臂完整矩阵（3 seed × 3 臂，同 seed 固定同卡）。
- `FAIL` → 修 bug 后重跑 smoke，禁止扩矩阵。
- `INCONCLUSIVE` → 登记「熵有轻微下降但未过阈值」，可允许调 `noise_scale` / `lb_alpha` 再跑一次
  smoke（**每次改动必须重新记录并说明理由**，不得静默调参凑 PASS）。

**禁止事项**：
- 不得用「初始 AUC == dense」当作路由是否工作的判据（已显式放弃函数保持）。
- 不得用跨 seed 均值差下结论（smoke 只有 1 seed）。
- 不得把 top-k 截断后的 gate 熵冒充 clean gate 熵。
- 不得事后把 PASS 阈值从 0.15 nats 悄悄下调。
