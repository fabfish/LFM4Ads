## 1. 审计结论

### 1.1 当前仓库没有完成过“router LR / expert LR / shared-expert LR 独立分配”实验

现有证据必须按真实语义解释：

1. `AdaTaskOptimizer` 只有一个 AdamW 参数组和一个全局 `lr`。所谓 encourage/suppress 是在 `optimizer.step()` 前对当前梯度乘因子，不是独立参数组学习率，也不是任务独立 optimizer state。
2. `PARAM_GROUPS` 目前只用于参数分类与冻结，不会生成 optimizer parameter groups。
3. `train_continual()` 在每个任务开始时重新创建默认 AdamW；所有可训练参数使用同一默认学习率。它没有 replay、EWC、旧任务损失、专家所有权或任务级冻结。
4. 旧 LR sweep 扫的是 **global LR**，而且主要是旧 V1 rx-only 输出分片 MoE，不能直接外推为低秩全维专家、TCMR 或持续学习的 block-wise LR。
5. 当前 TCMR 是低秩全维 routed experts + task/data router，**没有 always-on shared expert**；DNN、Sparse embedding 可视为共享 backbone，但不能在报告中冒充“共享专家”。
6. 旧部分路由模型虽有 shared 分片，但专家只输出固定坐标分片，不是标准可互换全维专家；其 top-k 还会计算所有专家，不能支撑真实 sparse-compute 结论。

因此，目前最多只能说“已有全局 LR 与梯度缩放观察”，不能说“已经找到不同子任务对 router/shared/sparse experts 的最佳学习率”。

### 1.2 已有结果中可保留的事实

### 1.3 既有结论中的主要问题

1. **把 pre-Adam gradient scaling 称为学习率。** 对 AdamW，常数梯度缩放会同时进入一、二阶矩，稳态下大体抵消。
2. **AU 统计不是模块总更新量。** 当前 hook 对同一模块内每个 parameter tensor 依次更新同一个 EMA key，结果依赖参数遍历顺序；它不等于模块梯度平方范数，也不等于实际 Adam 更新范数。
3. **幅度没有方向。** AU 大可能是有益共识，也可能是破坏性冲突；只按 AU promote/suppress 无法判断遗忘方向。
4. **旧 router 结论被机制判别推翻。** router suppression 的收益可由 frozen uniform router 平替，故不能解释成“学到了更好的专家分工”。
5. **旧 continual 证据等级低。** 单 seed、单 order、旧 checkpoint、旧输出分片 MoE、每任务重置 optimizer、没有强 CL baseline；且旧 `compute_forgetting` 历史口径存在 D12 baseline 问题。
6. **非活动任务参数也可能衰减。** task embedding 是一个 dense parameter；若旧行梯度为零但参数仍在 AdamW parameter group 中，decoupled weight decay 仍会改变旧行。真正冻结必须排除该参数/行或令该组 `weight_decay=0`，不能只依赖零梯度叙述。
7. **静态 AUC 不能代替持续学习。** TCMR 静态关卡 INCONCLUSIVE 不证明 CL 无效，但它阻止把任务路由当作已成立组件；后续必须把 BWT/LA 设为主终点，而不是继续用静态 pooled AUC 给机制背书。

## 2. 共享/专精专家与路由的统一数学定义

### 2.1 前向

令任务为 `s`，第 `l` 层输入为 `h`，Cross 残差基向量为 `x0`。建议研究的标准全维 shared-and-routed 层为：

\[
p_e=\operatorname{TopKSoftmax}(z)_e,\qquad
z=R_{\phi_r}(h,e_s),
\]

\[
[\rho_h,\rho_r]=\operatorname{softmax}(A_{\phi_a}(h,e_s)),
\qquad \rho_h+\rho_r=1,
\]

\[
m=\rho_h E_h(h;\theta_h)+
\rho_r\sum_{e=1}^{K}p_eE_e(h;\theta_e),
\]

\[
h^+=h+x_0\odot m.
\]

参数块为：

- `allocation gate`：\(\phi_a\)，分配 shared/specialist 路径容量；
- `always-on shared expert weights`：\(\theta_h\)；
- `task-conditioned specialist router`：\(\phi_r\)；
- `routed specialist expert weights`：\(\theta_e\)。

若 shared expert 严格 always-on，可固定 \(\rho_h=1\)，删除 \(\phi_a\)。不能为了凑四块而虚构“shared expert router”。当前 TCMR 只有 \(\phi_r,\theta_e\) 加共享 backbone，不具备上述完整四块。

### 2.2 专家权重梯度

令

\[
r=\frac{\partial L_s}{\partial h^+},\qquad
\delta=r\odot x_0.
\]

则 shared expert 的梯度为：

\[
\nabla_{\theta_h}L_s
=\rho_h J_{E_h,\theta_h}^{\top}\delta.
\]

第 `e` 个 specialist expert 的梯度为：

\[
\nabla_{\theta_e}L_s
=\rho_r p_e J_{E_e,\theta_e}^{\top}\delta.
\]

这给出两个关键事实：

1. shared expert 每个样本都更新，累计暴露量高；若与所有任务共享同一大 LR，容易成为遗忘主通道。
2. specialist 的更新天然乘以门控概率与激活频率。top-k 外的专家梯度严格为零；稀疏专家每个 global step 的有效更新次数更少，但不能因此机械设 \(\eta_e\propto1/q_e\)，否则会把低频梯度方差放大为爆炸更新。

令专家 `e` 在任务 `s` 上的激活率为 \(q_{e,s}=P(e\in\mathcal K\mid s)\)。其每个 global batch 的期望一阶更新规模近似为：

\[
\mathbb E[\Delta\theta_e\mid s]
\approx-\eta_{e,s}q_{e,s}\,\mathbb E[u_{e,s}\mid e\text{ active}],
\]

其中 \(u\) 是优化器预条件后的方向。学习率应同时考虑 `load`、方差和跨任务冲突，不应只按 \(1/q\) 补偿。

### 2.3 specialist router 梯度

对 softmax logits `z`，记 \(\bar E=\sum_jp_jE_j(h)\)，则：

\[
\frac{\partial L_s}{\partial z_e}
=\rho_r p_e\langle\delta,E_e(h)-\bar E\rangle.
\]

router 只有在某专家相对当前混合输出能降低任务损失时才收到明确方向；当专家输出相近时，\(E_e-\bar E\approx0\)，router 梯度天然弱且噪声占比高。当前 TCMR 的低 task-expert MI 与无稳定 AUC 增益，和“router 信号弱”一致。

若使用 hard top-k，未选专家对主任务损失的 router/expert 梯度为零，边界附近的选择又不连续。此时较大的 router LR 会增加 route churn，并把同一输入频繁改派给尚未适配的专家；因此本仓库证据支持“router 先冻结、后小步解冻”，不支持 router 与 expert 同 LR 起跑。

### 2.4 allocation gate 梯度

设 allocation logits 的 routed 分量为 `a_r`，则二分类 softmax 下：

\[
\frac{\partial L_s}{\partial a_r}
=\rho_h\rho_r
\langle\delta,\bar E-E_h(h)\rangle.
\]

allocation gate 学的是 shared 与 specialist 的相对优势，不是 specialist 内部的专家选择。其 LR 过大时，单一新任务可迅速把流量全部推向某一路径，造成共享知识被旁路或 specialist 路径塌缩；故它应比 specialist weights 更慢，并受路径占比与漂移约束。

## 3. 为什么当前 AdaTask 缩放不等于真实 task-specific LR

### 3.1 AdamW 的缩放抵消

当前实现先令 \(g'_t=c_tg_t\)，再送入同一个 AdamW：

\[
m_t=\beta_1m_{t-1}+(1-\beta_1)c_tg_t,
\]

\[
v_t=\beta_2v_{t-1}+(1-\beta_2)c_t^2g_t^2,
\]

\[
\Delta\theta_t=-\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}-\eta\lambda\theta_t.
\]

若 `c` 长时间近似常数，则 \(m\mapsto cm\)、\(v\mapsto c^2v\)，所以：

\[
\frac{cm}{\sqrt{c^2v}}\approx\frac{m}{\sqrt v}.
\]

因此常数 promote/suppress 在 Adam 稳态中大体被抵消；只剩 `epsilon`、瞬态、符号变化和 weight decay 相对比例等效应。旧网格测到的是“改变进入共享 Adam 状态的梯度历史”，不是可解释的 task LR。

### 3.2 真正的 block/task LR

研究上界应为每个任务 `s`、参数块 `q` 维护独立 moments：

\[
m_{q,s}^{t}=\beta_1m_{q,s}^{t-1}+(1-\beta_1)g_{q,s}^{t},
\]

\[
v_{q,s}^{t}=\beta_2v_{q,s}^{t-1}+(1-\beta_2)(g_{q,s}^{t})^2,
\]

\[
u_{q,s}^{t}=\frac{\hat m_{q,s}^{t}}{\sqrt{\hat v_{q,s}^{t}}+\epsilon},
\]

\[
\Delta\theta_q=-\sum_s w_s\eta_{q,s}u_{q,s}^{t}.
\]

这是 `Exact Task-State Optimizer`，状态复杂度 \(O(TP)\)，只适合小规模因果对照。

可扩展版本保留共享参数级预条件器，只保存 `task × block` 低维统计，并在预条件后缩放：

\[
\Delta\theta_q=-\sum_s w_s\eta_{q,s}
\frac{g_{q,s}}{\sqrt{\hat v_q}+\epsilon}.
\]

这里 \(\eta_{q,s}\) 作用在分母之后，才不会被二阶矩同步抵消；状态约为 \(O(P+TQ)\)，`Q` 为参数块数。

## 4. 从遗忘约束推导学习率

### 4.1 一阶冲突

对旧任务聚合损失 \(L_{old}\) 和新任务 `t`，在参数块 `q` 上执行：

\[
\Delta\theta_q=-\eta_{q,t}d_{q,t}.
\]

旧任务的一阶变化为：

\[
\Delta L_{old}
\approx-\eta_{q,t}
\langle g_{q,old},d_{q,t}\rangle.
\]

- 内积为正：新任务更新帮助旧任务，可允许较大 LR；
- 内积为负：新任务更新伤害旧任务，应减小 LR、投影冲突分量或改派 specialist；
- 只看 \(\|g\|^2\) 的 AU 无法区分两者。

### 4.2 二阶安全上界

若 `L_old` 在该块上为 \(M_q\)-smooth，则：

\[
\Delta L_{old}
\le-\eta c_q+\frac{M_q}{2}\eta^2\|d_{q,t}\|^2,
\quad c_q=\langle g_{q,old},d_{q,t}\rangle.
\]

给定允许遗忘预算 \(\varepsilon_q\)，充分条件为：

\[
\eta_{q,t}\le
\frac{c_q+\sqrt{c_q^2+2M_q\|d_{q,t}\|^2\varepsilon_q}}
{M_q\|d_{q,t}\|^2}.
\]

当 \(c_q<0\) 时上界会明显缩小。这说明 block-wise LR 应由“旧任务重要性 × 新旧梯度方向 × 更新范数”决定，而不是为所有任务预设同一 encourage/suppress 符号。

### 4.3 Fisher/EWC 形式

用旧任务 Fisher 对共享参数施加稳定性：

\[
L=L_t+\frac{\lambda_F}{2}
(\theta-\theta^{old})^\top F^{old}(\theta-\theta^{old}).
\]

若优化局部二次模型：

\[
g_t^\top\Delta+
\frac{1}{2\eta}\Delta^\top P\Delta+
\frac{\lambda_F}{2}\Delta^\top F^{old}\Delta,
\]

则：

\[
\Delta=-\eta(P+\eta\lambda_FF^{old})^{-1}g_t.
\]

坐标 `i` 的有效 LR 为：

\[
\eta_i^{eff}=\frac{\eta}{P_i+\eta\lambda_FF_i^{old}}.
\]

旧任务重要的 shared 参数自动慢更新；低 Fisher 的 specialist 残差参数保留塑性。该公式比“shared 一律小 LR”更准确，也给 EWC 与 block LR 的组合提供直接解释。

## 5. 当前场景的学习率先验

以下是**待实验检验的预注册先验，不是已有结论**。绝对值以旧 global-LR 平台为保守 anchor；低秩全维/持续学习必须重新扫描。

令 specialist expert 基准学习率为 \(\eta_e\)。

| 参数块 | 初始建议 | 理由 |
|---|---:|---|
| 新任务 head / 新 task-embedding 行 | `1.0 × η_e`，`weight_decay=0` | 仅服务当前任务，需要塑性；旧任务行必须完全冻结 |
| 新分配或当前任务拥有的 specialist experts | `1.0 × η_e` | 冲突残差的主要写入位置 |
| 被多个旧任务复用的 specialist experts | `0–0.5 × η_e`，由 cosine/Fisher 决定 | 冲突时冻结/投影，同向时允许复用 |
| always-on shared expert / shared backbone | `0.05–0.1 × η_e` + Fisher/EWC | 所有任务都经过，遗忘风险最高；只吸收跨任务共识 |
| global data router | 初始 `0`；解冻后 `0.02–0.1 × η_e` | 现有证据中 frozen 可平替 suppression，TCMR 静态收益不稳定 |
| 新任务 router embedding 行 | `0.1–0.25 × η_e`，`weight_decay=0` | 允许新任务选路，但避免一步改派；旧任务行冻结 |
| allocation gate | `0–0.05 × η_e` | 防止新任务快速旁路 shared path 或路径塌缩 |

绝对扫描：

\[
\eta_e\in\{2\times10^{-4},5\times10^{-4},10^{-3}\}.
\]

首选 anchor 为 `5e-4`，但报告必须写成“候选 anchor”；因为已有证据只证明 `5e-4–1e-3` global-LR 平台，未证明 `5e-4` 是 block-wise 最优。

必须额外满足：

1. 旧 task embedding/head 行不进入带 weight decay 的活动组；
2. router LR 与 expert LR 分开记录实际 update norm，而不只记录配置值；
3. top-k 前先在 soft routing 下过优化语义关卡；
4. 每个 block 记录 `raw grad norm / preconditioned update norm / parameter drift / Fisher-weighted drift`；
5. 所有按任务子梯度按 \(w_s=|B_s|/|B|\) 合成，保持每样本等权；
6. 对 shared block，负 cosine 优先投影或路由隔离，不用无限减小 LR 代替机制。

### 6.3 `Learning-Rate Semantics Invariant Gate`

**状态：implemented / authorized for invariant verification。**

先实现并通过 CPU/smoke 数值不变量：

1. `Pre-Adam Scaling Cancellation Check`：固定比例缩放在 Adam 稳态下不应被误报为同比有效步长；
2. `Post-Preconditioner Scaling Check`：预条件后倍率应与实测 update norm 比例一致；
3. `Inactive Task Row Immutability Check`：旧 task embedding/head 行在 step 后逐位不变，包括 weight decay；
4. `Selected Expert Update Isolation Check`：top-k 外专家与非拥有专家逐位不变；
5. `Sample-Weighted Task Gradient Conservation Check`：任务梯度合成与 full-batch 目标一致；
6. `Standard BWT Matrix Check`：BWT 必须用刚学完任务 `j` 时的 `A[j,j]`，不是统一用 task-0 或 pretrain baseline；
7. `Optimizer-State Provenance Check`：manifest 记录每个 block/task 的 LR、betas、weight decay、state sharing 和源码 hash。

任一失败：`blocked`，禁止启动 GPU 矩阵。

### 6.4 `Two-Task Conflict Learning-Rate Screen`

**状态：blocked by invariant gate。**

先用旧实验中遗忘较重的场景对做最小机制筛选；顺序必须双向，避免把 order effect 当方法效果：

- order A：`scenario-0 then scenario-3`；
- order B：`scenario-3 then scenario-0`；
- seeds：42 / 123 / 456；
- 同 seed 的所有 LR 模式固定同卡；不同 seed 可按 `seed_device_map` 跨设备并行；
- backbone：统一同一预训练点；soft routing；sample-weighted；相同 step 数和 early-stop。

按顺序筛选，禁止一次铺开笛卡尔积：

1. `Specialist Learning-Rate Anchor Screen`：task-head LR 固定 `5e-4`，仅扫描 \(\eta_e\in\{2e-4,5e-4,1e-3\}\)，shared/router 冻结；
2. `Shared-to-Specialist Learning-Rate Ratio Screen`：\(\eta_h/\eta_e\in\{0,0.05,0.1\}\)，沿用第 1 步 winner，router 冻结；
3. `Router-to-Specialist Learning-Rate Ratio Screen`：\(\eta_r/\eta_e\in\{0,0.05,0.1\}\)，沿用前两步 winner；
4. `Optimizer-State Semantics Comparison`：
   - `Shared-AdamW Uniform Learning Rate`；
   - `Shared-AdamW Pre-Adam Gradient Scaling`；
   - `Four-Block Post-Preconditioner Learning Rates`；
   - `Exact Task-State Four-Block Optimizer`。

唯一配置数按复用锚点约 7 个 LR 配置 + 4 个 optimizer 语义臂；实际 run manifest 在启动前机械去重。不得把探索途中 winner 直接写成最终结论。

主终点：双向 order 上的标准 BWT；保护指标：Learning Accuracy、worst-task forgetting、pooled/macro AUC、Fisher-weighted shared drift、route churn。

解锁条件：

- 每个 order 内 3 seed 的相对 baseline BWT 差严格同向；
- 平均配对差超过该 order baseline 的 3-seed 极差；
- Learning Accuracy 不出现三 seed 同向恶化；
- router 解冻必须同时降低 routed-expert conflict 或 route churn，并改善 BWT；只提高 task-expert MI 不算通过。

否则判 `INCONCLUSIVE` 或 `FAIL`，不进入全任务矩阵。

### 6.5 `Continual-Learning Baseline Matrix`

**状态：blocked by two-task gate。**

任务：8 个正式报告场景；至少 3 orders × 3 seeds。每学完任务后评估全部已见任务。

最低基线：

1. `Dense Sequential Fine-Tuning`；
2. `Dense Elastic Weight Consolidation`；
3. `Dense Reservoir Replay`；
4. `Frozen Backbone with Task Adapter`；
5. `Mixture-of-Experts Sequential Fine-Tuning`；
6. `Mixture-of-Experts Four-Block Learning Rates`；
7. `Exact Task-State Four-Block Optimizer`；
8. `Branch-Train-MiX`（若成本无法对齐，必须单列训练/存储预算，不得隐藏）。

主终点：标准 BWT。共同保护终点：Learning Accuracy、average/worst forgetting、流量加权漂移、新任务达到阈值所需 steps。静态 pooled AUC 只能作为保护指标。

方法晋级条件：

- 对每个 order，3 seed 的 BWT 配对差同向；
- 总体提升超过预注册 baseline noise floor；
- Learning Accuracy 与新任务收敛速度不系统性下降；
- 至少超过 `Dense Elastic Weight Consolidation` 和 `Mixture-of-Experts Sequential Fine-Tuning`；
- 若不超过 replay，只能声称无回放或低存储折中，不能声称总体最优 CL。

### 6.6 `Alignment-Aware Shared-and-Specialist Update Ablation`

**状态：blocked by baseline matrix。**

只对晋级方法做必要消融：

- `Update-Magnitude Only`；
- `Gradient-Alignment Only`；
- `Update-Magnitude Times Alignment`；
- `No Fisher Stability`；
- `Frozen Specialist Router`；
- `Always-On Shared Expert versus Learnable Allocation Gate`；
- `Shared Optimizer State versus Exact Task State`。

只有完整方法稳定超过 `Four-Block Post-Preconditioner Learning Rates`，才能证明收益来自 alignment-aware 规则，而不是简单设置了多个 parameter groups。

### 6.7 `Sparse Continual Routing Scale-Out`

**状态：blocked。**

仅在前述持续学习关卡 PASS 后，才允许 soft → top-2 → top-1，并且必须实现真实 sparse dispatch。比较 same-active、same-total、same-latency dense；记录 expert load、overflow、通信和 wall-clock。Stage B 已失败，故当前禁止预写 sparse scaling 收益。

## 7. 长程 watcher 执行协议

任何 GPU 矩阵启动前必须依次完成：

1. 新建对应时间命名驱动文档和不可覆盖 authorization/manifest；
2. 运行 invariant verifier 与 smoke；
3. 冻结源码、数据、驱动 SHA-256；
4. `seed_device_map` 保证同 seed 的全部对照同卡，不同 seed 才可跨卡并发；
5. 用 detached 训练进程 + 前台 `sleep <=300s` tick 挂起，不能把后台任务当 watcher；
6. 每 tick 复核 PID、GPU、日志 mtime、产物计数和异常；
7. 每个状态迁移回写 docs/manifest；自然退出且产物齐全才结束；
8. 失败 run 不静默丢弃，重试原因和源码 hash 必须登记。

本文只完成计划与审计。`Learning-Rate Semantics Invariant Gate` 通过并获得新授权前，不启动长程 watcher。

## 8. 当前最终判断

1. 当前最可信的优化先验不是“提高 expert LR”，而是：**specialist 保持中等 LR，shared 显著更慢，global router 先冻结；新任务专属行可较快、旧行严格不动。**
2. 推荐起点是 `η_expert=5e-4`、`η_shared=0.05–0.1×η_expert`、`η_global_router=0`、`η_new_task_router=0.1–0.25×η_expert`；这些是预注册候选，不是结果。
3. 当前 AdaTask 的梯度乘因子不能回答 task-specific LR 问题；应先建立 post-preconditioner block LR 与 exact task-state 上界。
4. shared 参数只吸收跨任务同向信号；冲突残差应写入 specialist，而不是靠把所有 LR 同时调低来“避免遗忘”。
5. TCMR 静态路由关卡为 INCONCLUSIVE，故 router 解冻必须以 BWT/LA 和冲突下降为条件；task-expert MI 或低熵不能单独作为成功。
6. 旧持续学习结果值得复验，但不能作为当前 claim。下一项可授权工作应是 `Learning-Rate Semantics Invariant Gate`，不是直接跑 8-task 大矩阵。
