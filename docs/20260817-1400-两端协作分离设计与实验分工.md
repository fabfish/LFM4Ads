## 一、为什么必须做分离设计（不是流程洁癖）

本项目的全部结论都建立在**配对差**上：\(\Delta = \mathrm{AUC^{moe}} - \mathrm{AUC^{dense}}\)（同 seed）。配对之所以有效，是因为两臂共享了一切混杂因子（数据文件、随机数流、GPU 型号、cuDNN 版本、TF32 开关、torch 版本）。

**一旦把同一个配对的两臂分到两台机器，这些混杂因子就全部回到 Δ 里**，而它们的量级是未知的、可能与效应（+0.005）同阶。届时 Δ 无法归因于"MoE vs dense"，整个实验作废。

> 补充（2026-08-17）：两端共享同一套 CephFS 挂载，**数据文件是同一份**（见 [AGENTS.md §6](../AGENTS.md)），这消除了"数据副本不同"这一项混杂，但 **GPU 型号 / cuDNN / TF32 / torch 版本 / 随机数流仍是各 machine 独立的**，因此 §2.1 的"禁止跨 site 相减"照常有效——共享挂载只让数据自建变为可选，**不改变隔离纪律**。

因此分离设计的**唯一硬目标**：让两端各自产出**site 内自足**的判定，两端之间只交换**结论与代码**，绝不交换需要相减的数字。

## 二、分离规范（强制，六条）

### 2.1 科学隔离：配对绝不跨 site

- **分配粒度 = 整个实验**（含其 dense 对照臂），不是"同一实验的不同 seed"。
- 每个 site 的每个实验必须**自带 dense 臂 4 seed**，并用**自己的 dense 臂**算噪声地板。
- 禁止拿 site B 的 moe 减 site A 的 dense；禁止用 site A 的地板 0.00135 去判 site B 的效应。
- 两端结论汇总时，只并列"各自的 Δ、各自的地板、各自的判定"，**不做跨 site 的合并均值**。

### 2.2 产物命名空间隔离（避免覆盖与续跑误判）

| 产物 | site A | site B |
|---|---|---|
| run json 目录 | `cache/macro_auc_27k/` | **`cache/macro_auc_27k_siteB/`** |
| 日志目录 | `logs/macro_auc_27k/` | **`logs/macro_auc_27k_siteB/`** |
| 矩阵状态 | 各自目录下的 `matrix_state.json`（**天然隔离，不会互相覆盖**） |
| run tag 前缀 | 无前缀（历史兼容） | **`b0repro_` / `b1_` / `b2_` / `b3_`** |
| 判定产物 | `cache/macro_auc_27k/*_decision.json` | `cache/macro_auc_27k_siteB/*_decision.json` |

实现方式：site B 全部通过 `LFM_MACRO_OUT=$PWD/cache/macro_auc_27k_siteB` 驱动（runner 的 `LOG_DIR` 自动跟随 `OUT_DIR`，见 `run_macro_auc_matrix.py:35-36`）。

**每个 run json 必须带 `provenance.site`**（见 §2.6 待办 T1）。

### 2.3 git 隔离：site B 分支自由开发，合并时审阅

- site B 在分支 **`site-b/<实验名>`** 上自由新增或修改实验代码、预注册并启动实验，**不直接推 main**。
- site A 不再承担开跑前的代码审阅；只有 site B 分支需要合并进 `main` 时，site A 才审阅实现语义、证据链和文件冲突。
- 两端可以在各自分支修改同一路径，但必须保持实验命名空间和证据隔离；合并时不得静默覆盖，必须明确解决差异。

| 文件 | 分支开发与合并规则 |
|---|---|
| `model.py`、`experiments/**`、`scripts/**` | site B 可在自己的分支自由修改并开跑；合并进主线时由 site A 审阅 |
| `results/INDEX.md`、`docs/NEXT.md` | 主线登记在合并审阅时由 site A 处理；site B 可在独立结论文档中先记录完整证据 |
| `cache/*_siteB/**`、`logs/*_siteB/**` | site B 独立命名空间，site A 不覆盖 |
| `docs/` 新增预注册和结论文档 | 各自使用独立文件；site B 文件名带 `-siteB` 后缀 |

## 三、site B 任务队列（三卡，按顺序）

**统一口径（全部沿用，唯一变量见各任务）**：KuaiRand-27K、轻量模型（去三大 ID 表，dim=330，869,525 参数）、`balanced` loss、K=5、lr=1e-3、batch 10000、`max_epochs 20 / patience 10`、**主端点 macro AUC（8 场景等权，test）**、模型选择 = macro valid 精确 argmax、4 seed(42/123/456/789) 同卡配对。

### B0：preflight + dense 基线复现 + 专家利用率诊断（≈4h，必须先做）

**三个目的一次达成**，这是 site B 的"入场券"：

1. **建立 site B 自己的 dense 基线与噪声地板**：dense × 4 seed（tag `b0repro_dense_s*`）。
2. **可比性验收**：与 site A 的 E10 dense 臂逐 seed 比对，容差 **5e-4**（`preflight_site.py --check-baseline`）。
   - 4/4 seed 在容差内 → site B 视为可比，可继续 B1–B3；
   - 任一 seed 超容差 → **停止**，先排查（TF32、数据副本、torch 版本），不得带着未解释的偏差往下跑。
   - 注意：这是**可比性检查**，不是配对差；即使超容差，site B 仍可做 site 内自足的实验，但必须在结论中登记"绝对值与 site A 不可比"。
3. **E12 专家利用率诊断**（原计划 E12，移交 site B）：moe(K=5, top_k=2) × seed 42 一个 run，训练结束 dump 3 层 × 15 场景 × 5 专家 = **225 个 router 权重**，还原全部 dispatch 决策（零额外推理成本）。

**E12 判据（沿用原冻结值，不得改）**：

| 观测 | 判定 | 后续 |
|---|---|---|
| 专家覆盖数 = 5 且负载 max/min ≤ 2 | 已分化 | 粒度是瓶颈 → B2 优先 |
| 覆盖 ≤ 3 或负载 max/min > 3 | 坍缩 | 先做 load-balance（B2b）|
| 覆盖 4、负载 2~3 | 部分分化 | B2 优先，B2b 补做 |

**禁止**：不得因诊断结果改判 E10/E11 的 PASS（那由 test macro 配对差独立支撑）。

产物：`cache/macro_auc_27k_siteB/run_b0repro_*.json`、`expert_usage_siteB.json`、`preflight_site_B.json`

### B1：top_k 单调性（原 E14，≈4h，独立无依赖）

**问题**：top_k 5(软)→2 使收益 ×2.66，继续到 **1**（每场景只走 1 个专家）会继续涨（机制="越特化越好"）还是回落（机制="存在最优协作度"）？

| 臂 | 配置 | run 数 |
|---|---|---|
| dense | 复用 B0 的 4 run | 0（复用） |
| moe top_k=2 | 复现 site A 最优形态，同时作 site B 内的参照 | 4 |
| **moe top_k=1** | **本实验的唯一变量** | 4 |

- 参数量**完全不变**（top_k 只改激活，不改参数）→ 严格公平。
- **不得声称"省算力"**：当前实现是激活稀疏（5 个专家仍全算），site A 实测 wall 0.98×。

**判据（冻结）**：\(\Delta_1 = \mathrm{macro(top\_k{=}1)} - \mathrm{macro(dense)}\)，同 seed 配对，地板 = site B 自己的 dense 臂 2×SD。

| 观测 | 结论 |
|---|---|
| \(\Delta_1 > \Delta_2\) 且 4/4 正 | 单调"越特化越好" → 值得做真条件计算（省算力且更强） |
| \(\Delta_1 < \Delta_2\) 但 > 地板 | 存在最优协作度（top_k=2 最优），机制 = "隔离 + 少量协作" |
| \(\Delta_1 <\) 地板 | 过度特化有害，专家间协作必要 |

### B2：router 粒度升级 —— 关键 MoE 改动（原 E13，≈12h，依赖 T2）

**问题**：当前 `ScenarioRouter = Embedding(15, K)` 只有 **15 种 gate 模式**（每场景一套固定权重，**与样本内容完全无关**）。MoE 的本质是"按输入条件化"，**样本级路由从未测过**——这是整个设计里表达力最弱的一环。

| 臂 | router | gate 模式数 | router 参数 |
|---|---|---|---|
| A（基线） | `ScenarioRouter`（= B1 的 top_k=2 臂，复用） | 15 | 225 |
| **B** | `DataRouter = Linear(330, 5)`，样本级 | 连续 | **4,965** |
| C | `Hybrid = Linear(330,5) + Embedding(15,5)` 后 softmax | 连续 + 场景 | 5,190 |

- 全部 top_k=2 硬路由、K=5、balanced loss，**唯一变量 = router 类型**。
- 零初始化保持"初始等价 dense"（gate ≡ 1）。
- **参数不守恒必须登记**：B 比 A 多 4,740 参数（占模型 0.55%）。**不得表述为"参数量相同"**。缓解论证：dense-widened 4× 容量收益 ≈0（`docs/20260814-2111`），故 0.55% 的容量收益应可忽略——**但这是推理不是测量，必须在结论中显式写出这条推理链**。

**判据（冻结）**：\(\Delta_B = \mathrm{macro(B)} - \mathrm{macro(A)}\)，同 seed 配对，site B 地板。

| 判定 | 条件 | 含义 |
|---|---|---|
| PASS | 4/4 正且均值 > 地板 | 样本级路由有额外收益 → 粒度确是瓶颈 |
| FAIL | 4/4 负 | 场景级已足够，样本级引入噪声 → 粒度路线关闭 |
| INCONCLUSIVE | 变号或在地板内 | 不解释；允许按原口径扩 seed |

C 臂为辅助：若 B FAIL 而 C PASS → "场景信息必要 + 样本信息有增量"。

**B2b（条件解锁，仅当 B0 判坍缩）**：load-balance loss `lb = K·Σ_i(frac_i × mean_gate_i)`，α ∈ {0.01, 0.05}，4 seed，≈8h。
