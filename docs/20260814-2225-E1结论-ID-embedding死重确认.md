## 一、结论一句话

把占总参数 **99.19%** 的三张 ID embedding 表（`video_id`/`author_id`/`music_id`，83,984,250 参数）
**从零重训练时彻底剔除**，pooled test AUC **无可测变化**（Δ = +0.000688 / +0.000220，2/2 seed
均在噪声地板 0.001 内），同时**参数量 −99.31%、每 epoch wall-clock −33%（1.48× 加速）**。

E0b 的推理期证据（清零 Δ=−0.000193）由此升级为**重训练必要性结论**：**这 84M 参数是死重，不是瓶颈。**

## 四、结论边界（登记，事后不得放宽）

1. **"无可测差异" ≠ "更好"**。两 seed 的 Δ_id 虽同为正、且 peak valid 也一致为正，但 |Δ| 均 < 0.001
   噪声地板，**只能判"无净贡献"**，不得写成"删除 ID 表提升 AUC"。
2. **预算边界**：`lr=1e-3`、15 epoch、batch 10000、from scratch、2 seed。不外推到更长预算、
   更大数据或其他数据集。两臂在 epoch 2–4 即达峰，说明预算不是限制因素。
3. **口径差异说明**：本轮 `full` 臂 test AUC（0.7810/0.7818）高于历史 `dcnv2_vanilla.pt` 的 0.777490，
   原因是修复后的 **best-state 精确 argmax**（旧实现有 0.001 死区，会把 best 钉在早期 epoch）
   + `GpuBatches` shuffle 训练。这是口径改进，不是数据泄漏；两者不可混用作对照。
4. **`iddrop` 只是工程对照**：其 dim=330 连带缩小了 cross 层，因此不作主判定
   （虽然"cross 容量无效应"已由 dense-widened 独立证实，Δ_drop 变号也与此一致）。
5. **不推广到所有 ID 特征**：结论限于 KuaiRand-1K 当前切分与"裸 ID 查表"这一建模方式。
   它说明的是**这种用法**没交出信号（平均 2.6 次曝光、test 74% OOV），
   不是"ID 信息本身无用"——后者正是 E2 要测的。

## 五、这改变了什么

### 5.1 三条路线被同时钉死

| 路线 | 状态 |
|---|---|
| cross 层容量 / capacity-MoE | 已关闭（dense-widened 4× 无收益 + 稀疏代价 −0.001） |
| embedding 容量（加宽） | **关闭**（现有 84M 容量根本没被用上，加宽前提不存在） |
| "参数最多处即瓶颈"这一推理方式 | **禁用**（97.9% 参数贡献 −0.0002） |

### 5.2 有效模型其实只有 0.58M 参数

全部预测能力来自 33 个低基数字段（embedding 合计 **33,140** 参数）+ cross/DNN/head（551,115）。
依赖度前三：`tag`(−0.0066) / `upload_type`(−0.0053，**320 参数**) / `user_id`(−0.0049)。

**这是后续实验的新默认基线**：`iddrop`（0.58M 参数、7.1s/epoch）替代 84.7M 的 full 模型，
使 3 seed × 多配置矩阵变得廉价——**这是 E1 除结论之外最实用的产出**。

### 5.3 新的科学问题（E2 起）

问题从"容量"彻底转为"**信息与泛化**"：`video_id` 平均 2.6 次曝光、test 74.19% OOV，
裸 ID 查表在结构上无法泛化。**E2 的假设**是：ID 不可泛化，但 ID 的**属性与统计**可以——
频次分桶、时序安全的历史 CTR 编码、作者/音乐侧聚合、`tag`×`upload_type` 交叉。
判据仍是同 seed 配对差越过 0.001 地板。
