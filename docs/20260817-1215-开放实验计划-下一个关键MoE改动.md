## E12：专家利用率诊断（最高优先级，必须先做）

### 假设与用途

**假设**：硬路由 top_k=2 的收益来自"不同场景路由到不同专家"。若实际发生**专家坍缩**
（所有场景都选同样的 2 个），则收益另有来源，且存在未被利用的容量。

**为什么必须先做**：它的结果**决定 E13/E14 的设计**——
- 坍缩 → 优先加 load-balance 机制（E12b），而不是升级 router 粒度；
- 已分化 → 粒度是新瓶颈，直接做 E13。

### 关键成本优势：只需 225 个数

`ScenarioRouter` 的 gate **完全由 `Embedding(15, K).weight` 决定**（只看 tab，与样本内容无关）。
3 层 × 15 场景 × 5 专家 = **225 个浮点数**即可完全还原全部 dispatch 决策。
故只需在训练结束时把 router 权重 dump 进 run json，**零额外推理成本**。

### 实现

1. `experiments/main_macro_auc.py`：训练结束（load best_state 后）dump
   `[layer.router.embed.weight for layer in model.cross_layers]` 到 run json 的
   `router_weights` 字段（scenario routing 时）。
2. `scripts/diagnose/diagnose_expert_usage.py`：从 router 权重重建
   - 每层的 `gate = softmax(w)*K`、top-2 选择矩阵（15 场景 × 5 专家）；
   - 指标：**路由熵**（每场景 gate 分布的熵，均匀=ln5=1.609）、
     **专家覆盖数**（被至少一个场景选入 top-2 的专家数，满=5）、
     **场景-专家 dispatch 矩阵**、**专家负载**（每专家被多少场景选中，均匀=6）。

### 成本

重跑 1 个 run（seed 42，top_k=2，轻量）≈ **50 min**（3.4min/epoch × ~15 epoch）。

### 判据（冻结）

| 观测 | 判定 | 后续动作 |
|---|---|---|
| 专家覆盖数 = 5，且负载 max/min ≤ 2 | **已分化** | 粒度是瓶颈 → 做 **E13** |
| 专家覆盖数 ≤ 3，或负载 max/min > 3 | **坍缩** | 容量未用满 → 先做 **E12b（load-balance）** |
| 覆盖 4，负载 2~3 | **部分分化** | E12b 与 E13 都做，E13 优先 |

**禁止**：不得因诊断结果不好看就改判 E10 的 PASS（E10 的结论由 test macro 配对差支撑，
与 dispatch 分布无关）。

### E12b（条件解锁）：load-balance loss

若判定为坍缩，加 `lb_loss = K * Σ_i (frac_tokens_i × mean_gate_i)`（Switch Transformer 式），
系数 α ∈ {0.01, 0.05}（1K 上曾用 0.01 且已修过 8× 归一化 bug），4 seed。
判据：Δ vs 无 lb 的 top_k=2，同 seed 配对，地板 0.00135。成本 8 run ≈ 8h。

## E13：router 粒度升级 —— 关键 MoE 改动

### 假设

当前 `ScenarioRouter` 只有 **15 种 gate 模式**，是整个设计里表达力最弱的一环。
**样本级路由（DataRouter = `Linear(dim, K)`）能否带来额外收益？**
这是"下一个关键 MoE 改动"：从**场景条件化**升级到**输入条件化**。

### 三臂设计

| 臂 | router | gate 模式数 | router 参数 |
|---|---|---|---|
| **A（基线）** | `ScenarioRouter`（现状，E10） | 15 | 225 |
| **B** | `DataRouter = Linear(330, 5)`，样本级 | 连续 | **4,965** |
| **C** | `Hybrid`：`Linear(330,5) + Embedding(15,5)` 相加后 softmax | 连续+场景 | 5,190 |

- 全部 **top_k=2 硬路由**、K=5、balanced loss（与 E10 同口径，唯一变量是 router 类型）。
- `DataRouter` 已存在于 `model.py`；需给 `main_macro_auc.py` 加 `--routing {scenario,data,hybrid}`
  并实现 `HybridRouter`。
- **零初始化**保持"初始等价 dense"的性质（DataRouter 已零初始化 → softmax 均匀 → gate≡1）。

### 参数公平性（必须登记）

B 比 A 多 **4,740** 参数（占轻量模型 0.55%）。这**不再是严格守恒**，故需一个
**dense-matched 对照**：给 dense 臂加一个同等参数量的无用线性层（或直接报告
"B 相对 A 的收益 ≥ 4740 参数的容量收益上界"）。
考虑到 dense-widened 已证明"cross 层 4× 容量收益≈0"，0.55% 的容量收益应可忽略，
但**必须在结论中显式登记这一推理链**，不得默认守恒。

### 成本

3 臂 × 4 seed = 12 run × ~1h ≈ **12h**（轻量模型）。

### 判据（冻结）

主终点 Δ_B = macro(B) − macro(A)，同 seed 配对：

| 判定 | 条件 | 含义 |
|---|---|---|
| **PASS** | 4/4 seed Δ_B > 0 且 mean > 0.00135 | 样本级路由带来额外收益 → 粒度确是瓶颈 |
| **FAIL** | 4/4 seed Δ_B < 0 | 场景级路由已足够，样本级引入噪声 → 粒度路线关闭 |
| **INCONCLUSIVE** | 变号或在地板内 | 不解释，允许按原口径扩 seed |

C 臂（hybrid）作为辅助：若 B FAIL 而 C PASS，说明"场景信息必要 + 样本信息有增量"。

## E14：top_k 单调性（含 top_k=1 极限特化）

### 假设

top_k：5(软) → 2 使收益 ×2.7。若继续降到 1（每场景只走 1 个专家 = 硬分配），
收益会继续涨（机制="越特化越好"）还是回落（机制="存在最优协作度"）？

### 设计

| top_k | 含义 | 状态 |
|---|---|---|
| 5 | 软路由全激活 | 已有（E7） |
| 3 | 中间点 | 已撤销（E10 缩减时） |
| 2 | 当前最优 | 已有（E10） |
| **1** | 极限特化 / 硬分配 | **本实验** |

- K=5、balanced loss、轻量模型，4 seed。**唯一变量是 top_k**，参数量完全不变。
- **附加价值**：top_k=1 等价于"每场景独占 1 个专家"，可与 E6（1K 完全隔离上界）呼应；
  且 top_k=1 是**真条件计算最容易落地的形态**（只需算 1 个专家）。

### 成本

4 run × ~1h ≈ **4h**。

### 判据（冻结）

Δ_1 = macro(top_k=1) − macro(dense)，同 seed 配对；并与 Δ_2（+0.005012）比较：

| 观测 | 结论 |
|---|---|
| Δ_1 > Δ_2 且 4/4 正 | 单调"越特化越好" → 后续做真条件计算（省算力 + 更强） |
| Δ_1 < Δ_2 但仍 > 地板 | 存在最优协作度（top_k=2 最优），机制是"隔离+少量协作" |
| Δ_1 < 地板 | 过度特化有害，专家间协作必要 |
