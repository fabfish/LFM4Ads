## 一、为什么 EWC 与 F1（优化器 baseline）是**两个不同设定**

| 维度 | F1（优化器状态共享度） | F2（EWC） |
|---|---|---|
| 训练设定 | **联合训练**：所有场景混合打乱，每个 batch 多场景 | **顺序训练**：场景按固定顺序依次上线，每个 batch 单场景 |
| 问题 | 如何平衡大小场景的梯度贡献 / 省优化器状态内存 | 学新场景时如何**不忘旧场景** |
| 机制 | 优化器状态分配（shared / decoupled / base+delta / 分层） | 正则：惩罚重要参数偏离旧解 |
| 服务方向 | adatask 提升 + scaling up | 持续学习（历史 Phase 4 遗留） |

故 F2 不能放进 F1 矩阵，需独立入口与判定。

## 二、EWC 定义（本文自包含）

Elastic Weight Consolidation（Kirkpatrick et al., 1612.00796）。顺序学完场景 \(s\) 后，用对角 Fisher 信息 \(F_s\) 记录"哪些参数对场景 \(s\) 重要"；之后训练新场景时，在损失上加二次惩罚：

\[
\mathcal{L}(\theta) = \mathcal{L}_{\text{current}}(\theta) + \frac{\lambda}{2}\sum_{s' < s}\sum_i F_{s',i}\,(\theta_i - \theta^*_{s',i})^2
\]

- \(F_s = \mathbb{E}\big[(\partial \mathcal{L}_s/\partial\theta)^2\big]\)（经验 Fisher，对场景 \(s\) 训练数据采样估计）；
- \(\theta^*_s\) = 场景 \(s\) 训练结束时的参数快照；
- 本实现用**对角** Fisher（每参数一个标量，存储 O(P)），非全 Fisher 矩阵。

## 三、设计（冻结）

| 项 | 取值 |
|---|---|
| 架构 | MoE(K=5, top_k=2)，轻量（869,750 参数），与 F1/E10 一致 |
| 场景顺序 | `[0, 1, 2, 3, 4, 5, 6, 8]`（8 个 macro 场景，与历史 main_continual 一致） |
| 每场景训练 | 探索阶段：1 epoch，子采样（每场景最多 N batch） |
| Fisher 估计 | 每场景训练后，用该场景 train 数据采样 ≤100 batch，梯度平方均值 |
| λ | 冻结 `λ ∈ {0.0（对照）, 1.0, 10.0}`（扫描，非事后调） |
| seed | 2（42, 123），探索阶段 |
| 指标 | ①最终 macro AUC（test，8 场景等权）②BWT = 训练序列结束后旧场景 AUC 相对其单独最优的回落 |

## 四、判定（冻结，探索阶段只报方向）

- 主指标 = **最终 macro AUC**（顺序训练全部完成后，在 test 上 8 场景等权）。
- 对比：\(\Delta_{\text{EWC}} = \mathrm{macro}(\lambda{>}0) - \mathrm{macro}(\lambda{=}0)\)（同 seed）。
- **BWT** 辅助：\(\mathrm{BWT} = \frac{1}{T-1}\sum_{t} \big(\mathrm{AUC}_t^{\text{final}} - \mathrm{AUC}_t^{\text{after task }t}\big)\)，负值 = 遗忘。EWC 应使 BWT 更接近 0（遗忘更少）。
- 探索阶段（2 seed + 子采样）只登记方向；正式判定需 4 seed + 全数据（backlog）。

## 五、实现路线与两个已识别的效率坑

1. **Split 重复读 6GB**：`dataset.Split(scenario)` 每次 `pd.read_feather` 全表（6GB）再 query，顺序训练 8 场景会重复读几十次。实现时须**读一次全表、按 tab 预分组缓存**，或直接对常驻 DataFrame 切片。
2. **顺序训练本身慢**：8 场景 × 各自 epoch。探索阶段用子采样（每场景 ≤N batch）+ 1 epoch/场景控制预算。
3. **复用**：`collect_task_gradients`（`task_role_optimizer.py`）已能算梯度，Fisher 对角 = 梯度平方均值，可复用；但 F2 单场景 batch 可用整批 backward（更快，无需 jacrev 15 vjp）。
4. 入口：`experiments/main_ewc.py`（新）；Fisher/惩罚模块放 `task_role_optimizer.py` 或独立 `ewc.py`。

## 六、与历史 main_continual 的关系

历史 `experiments/main_continual.py` 是 1K + K=4 capacity MoE（已关闭架构），发现 MoE 抗遗忘(BWT)优于 vanilla 22.5%。F2 在 27K + 轻量 MoE(K=5, top_k=2) 下重做，**新增 EWC 臂**（历史无 EWC），把"MoE 本身已抗遗忘"升级为"EWC 是否仍有增量"。
